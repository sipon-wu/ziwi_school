## 3. 知识点 ID 方案（m-G-C-I 体系）

### 3.1 现有约定（来自审计示例）

- `m-1-1-1` → 数学 / 1 年级 / 第 1 单元 / 第 1 知识点（"1-5 的认识"）
- `m-1-1-2` → 数学 / 1 年级 / 第 1 单元 / 第 2 知识点（"0 的认识"）
- `m-3-3-2` → 数学 / 3 年级 / 第 3 单元（时/分/秒）/ 第 2 知识点（"时分秒"）

可识别为 `{学科前缀}-{年级}-{单元序}-{知识点序}`。**但示例未体现「册（上/下）」编码**——同年级上、下册都有「单元 1」，4 段式会在上/下之间碰撞。

### 3.2 推荐语法（5 段，消除册碰撞）

```
{前缀}-{年级}-{册序}-{单元序}-{知识点序}
例：m-3-1-3-2  = 数学 / 3年级 / 上册 / 第3单元 / 第2知识点
```

- **年级编号**：小学 1–6，初中 7–9，高中 10–12。
- **册序**：上 = 1，下 = 2（高中「必修第一册」等按册映射，单列映射表）。
- **单元序 / 知识点序**：均按 KG 中「单元」「知识点」列表顺序 1-based 编号。
- **子知识点（Level 4）id**：父 id + `.` + 子序号，如 `m-7-1-1.1`。用于 `knowledge_seed.json` 展开。

### 3.3 学科前缀提案（待开发团队确认）

| 学科 | 前缀 | 学科 | 前缀 |
|---|---|---|---|
| 数学 | `m` | 地理 | `g` |
| 语文 | `c` | 历史 | `l` |
| 英语 | `e` | 道德与法治 / 思想政治 | `d` |
| 物理 | `p` | 科学（小学） | `s` |
| 化学 | `h` | | |
| 生物 | `b` | | |

> `m` 沿用现有；其余为提案，因这些学科目前在 product 中本就无 id，可从零定义。

### 3.4 锚定策略（关键）

- 数据团队**请求开发团队提供当前 product 的 `knowledge-graph.json` 与 `knowledge_seed.json`**（或至少 math1-6 / 语文1-6 部分）。
- 用脚本**解析现有 id**，对「已集成学科（数学 1-6、语文 1-6）」**逐条复用其现有 id**，保证前端 picker / AI tier 引用的连续性不断裂。
- 对新增学科，按 3.2 语法生成 id。
- **若现有文件实为 4 段式（无册）**：推荐整体迁移到 5 段式，由开发团队一次性更新对 168 条现有 id 的引用（量小、一次性）；数据团队可按开发团队选择执行「4 段沿用 / 5 段统一」任一种。

## 4. 交付物清单（数据团队产出）

| 编号 | 交付物 | 内容 | 数据来源 |
|---|---|---|---|
| D1 | `textbook-math.json` | 教材版本→年级→册→[{unit, kps:[id]}]，覆盖小学/初中/高中数学（人教版 / 人教版A版） | output/kg 数学类 + id 方案 |
| D2 | `knowledge-graph.json`（全量） | 前端图谱 + 知识点选取，Level-3 节点全量，含 id + difficulty | output/kg 全 138 文件 |
| D3 | `knowledge_seed.json`（全量） | 后端 AI 推理 / DB 初始化，含 Level-4 子知识点展开，含 id | output/kg + 高中 KG |
| D4 | `init_data_vX.sql`（刷新） | `tb_kg_node` / `tb_kg_edge` 全量落库（含 id + difficulty） | 重跑 `export_sql.py` |

### D1 结构（与审计示例一致）

```json
{
  "小学|数学|人教版|三年级|上册": {
    "3": {
      "上": [
        { "unit": "时、分、秒", "kps": ["m-3-1-3-2"] },
        { "unit": "万以内的加法和减法（一）", "kps": ["m-3-1-2-1", "m-3-1-2-2"] }
      ]
    }
  }
}
```

> **范围说明**：审计 P0 写「全版本 / 全年级 / 全册」，但 `textbook-math.json` 是**数学专用**连接器，且只覆盖本地已生成 KG 的数学版本（人教版小学/初中、人教版A版高中）。其余版本（如北师大版等 314 版本库中的非人教版）若无对应 KG，则该连接器暂不覆盖——如需覆盖须先补该版本 KG（不在本次范围）。

## 6. 给开发团队的待确认清单

1. **册编码**：现有 id 是否含册？4 段沿用还是统一 5 段？（决定 3.4 锚定方式）
2. **前缀表**：3.3 提案是否采纳？有无内部既有约定？
3. **Picker 范围**：`useKnowledgePicker` 是否仅数学需 `textbook-math.json`，还是各科目都需同类连接器（影响 D1 是否扩展为 `textbook-<学科>.json`）？
4. **锚定文件**：请提供当前 product 的 `knowledge-graph.json` 与 `knowledge_seed.json`（阶段 0 输入）。
5. **子知识点**：`knowledge-graph.json`（前端）是否只含 Level-3；Level-4 是否仅落 `knowledge_seed.json` / DB？（决定 D2 颗粒度）

- [ ] D1 `textbook-math.json` 存在且单元下拉可在前端正常填充；自动预选不再退化为「取前 6 个」。
- [ ] D2 / D3 覆盖审计 2.1 全部学科与学段（含初中全科、高中全科、英语全学段）。
- [ ] 所有知识点 `id` 唯一、符合约定；已集成学科（math1-6 / 语文1-6）id 与线上一致，无引用断裂。
- [ ] difficulty 字段全量保留 L1–L4，L3+L4 占比 ≥ 10%。
- [ ] D4 入库后 `tb_kg_node` 单元数与对应教材目录一致（以审计 1.2 人教版三年级上 9 单元为抽样校验）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 现有 id 与提案语法冲突 | 阶段 0 先解析锚定，冲突由开发团队拍板 4/5 段 |

| 大批量 id 重排导致线上引用失效 | 已集成学科严格复用现有 id，仅新增学科新分配 |
