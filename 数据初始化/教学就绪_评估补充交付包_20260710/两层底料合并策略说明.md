# 两层底料合并策略说明

> 备课课程包层（2,918本有课程包）与 教材层（3,637本注册表）需要合并为统一的 K12 底料全集。
> 两层的 bookId 命名空间**完全不相交**，不能直接按 bookId JOIN。

---

## 一、两层定位差异

| 维度 | 备课课程包层 | 教材层 |
|---|---|---|
| 数据内容 | 课件/教学设计/视频稿文本 | 教材注册表 + 预览图 |
| 文本来源 | **零 OCR，直接获取富文本** | 需 OCR 后获得文本 |
| 书数量 | 2,918 本（有课程包） | 3,637 本（含无课程包的书） |
| 粒度 | 课程包级（每课时一条） | 教材级（每本书一条） |
| 文本质量 | 高（精确、结构化） | 中（OCR后待确认） |
| 使用优先级 | **第一优先**（直接可用） | 第二优先（待OCR校对完成） |

**核心原则**：有备课包的书，直接取备课包文本（零OCR、高准确率）；无备课包的书，靠教材层 OCR 保底。

---

## 二、JOIN 策略（两层关联）

### 2.1 精确 JOIN（首选）

教材层的 `teachmeterial_ids` 字段直接指向备课包层的 bookId。**624 本教材有此字段**。

```sql
-- 伪代码
SELECT * 
FROM 教材层 m
JOIN 备课课程包层 p ON m.teachmeterial_ids @> ARRAY[p.bookId]
```

**覆盖**：624 本教材 → 可精确关联到备课课程包

### 2.2 签名 JOIN（回退）

对于没有 `teachmeterial_ids` 的教材，使用 `学段|学科|年级|册别|版本` 签名做字符串匹配。

**问题**：教材层的 `版本` 标签粒度更细，例如：
- 教材层：`人教版（B版）（主编：高存明）`
- 备课包层：`人教版（B版）`

**匹配规则**（按宽松度排序）：

```
规则1（精确匹配）：学段 + 学科 + 年级 + 册别 + 版本（完全相同）
规则2（前缀匹配）：学段 + 学科 + 年级 + 册别 + 版本（备课包层版本 ⊂ 教材层版本）
规则3（去掉版本）：学段 + 学科 + 年级 + 册别 （匹配后取教材层版本）
```

**预期覆盖率**：严格签名约 65%，前缀回退约 80%

### 2.3 JOIN 结果状态

| 类型 | 说明 | 预计占比 |
|---|---|---|
| A. 有备课包（精确） | 备课包层直接提供文本 | ~20% |
| B. 有备课包（签名） | 备课包层可匹配，文本可用 | ~45% |
| C. 无备课包 | 仅靠教材层 OCR 获取文本 | ~35% |

## 三、合并后的使用建议

### 3.1 RAG 检索优先级

```
查询时：
  1. 先查备课包层（46,918条富文本，评分可用）→ 命中即返回
  2. 若备课包层无结果 → 查教材OCR层（待OCR完成后）
```

### 3.2 年级字段说明

备课包层 17.2% 的 chunk 年级为空。在合并时，若备课包层缺年级，可从教材层回填：

```python
# 回填逻辑
if chunk['年级']为空:
    chunk['年级'] = 教材层.年级  # 教材层年级非空率≈82.8%
```

### 3.3 版本字段规范化

开发团队入库时，建议保留 `版本_原始` 和 `版本_规范化` 两个字段：

| 原始（备课包层） | 原始（教材层） | 规范化建议 |
|---|---|---|
| `人教版` | `人教版` | `人教版` |
| `人教版（B版）` | `人教版（B版）（主编：高存明）` | `人教版（B版）` |
| `北师大版` | `北师大版` | `北师大版` |

## 四、合并后的数据形态

最终 K12 底料全集 = 备课包层（A+B）+ 教材OCR层（C）

```
统一底料字段：
  chunk_id | 学段 | 学科 | 年级 | 册别 | 版本 | 单元 | 章节 
  | 来源类型（课程包 / 教材OCR）
  | 文本内容 | 置信度（OCR有/课程包无）
  | 关联课标条目 | 关联KG单元 | 版权标识
```

**OCR 回传完成前**：仅 A+B 可用（C 待补充）
**OCR 回传完成后**：A+B+C 合并为全集
