# 场景与互动规范（H5 专用）

> 本文件是 `courseware.h5` Skill 的领域知识。
> 教学性要求与风格语义见 `shared/`，本文件只讲 H5 特有的场景与互动。

---

## 一、场景（scene）怎么组织

一个 H5 课件 = 一条情节线，8~16 个场景。

### 典型节奏

```
开场（情境导入）→ 冲突/疑问 → 探究（2~4 个场景）→ 互动检验
   → 再探究 → 高潮互动 → 收束（对话总结）
```

### 各位置要点

| 位置 | 场景数 | 要求 |
|---|---|---|
| 开场 | 1~2 | 建立情境，抛出问题；**要有气泡** |
| 探究 | 3~6 | 对话推进，每场景一个知识点 |
| 检验 | 2~3 | **放互动**（quiz / reveal / draw） |
| 收束 | 1~2 | 角色对话总结，**不写"小结"标题** |

### 禁止

- ❌ 出现「学习目标」「课堂小结」「分层作业」页面（那是 PPT 的结构）
- ❌ 用 bullets 罗列要点（那是 PPT 的写法）
- ❌ 一页塞多个知识点

### 画面描述（每场景 1~2 句）

每个场景用 **1~2 句话**交代画面（角色、环境、情绪），便于渲染为儿童绘本风格。
写成普通句子即可（它就是旁白的一部分）：

```
海洋馆里，巨大的水族箱泛着蓝光。水滴们挤在荷叶上，好奇地张望。
```

⚠️ **不要**把它写成 `角色：内容` 的形状——那会被解析成一条气泡，凭空多出一个假角色。
（画面描述是"叙述"，气泡是"角色在说话"，两者形状必须区分。）

## 二、气泡（bubbles）

- 每条 **≤20 字**，口语化
- 每场景 2~4 条，太多会挤
- 角色要**性格区分**（如一个爱提问、一个爱抢答），不要三个人说一样的话
- 气泡推进情节，不是复述旁白

```json
"bubbles": [
  { "role": "老师", "text": "匀速行驶时，什么不变？" },
  { "role": "小明", "text": "速度 60 一直不变！" },
  { "role": "小红", "text": "那时间和路程在变。" }
]
```

## 三、互动九种，按教学目的选

| type | 教学目的 | 何时用 | 关键字段 |
|---|---|---|---|
| `read` | 朗读记忆 | 概念、公式、句子 | `reads:[{text,hint}]` |
| `readalong` | 跟读纠音 | 语言类 | `sentences:[{text}]` |
| `quiz` | 检验判断 | 辨析、计算 | `quiz:{question,options,correct}` |
| `reveal` | 先想再看 | 例题解答 | `prompt` / `answer` |
| `draw` | 动手建构 | 画图、连线、标注 | `drawTitle` / `drawHint` |
| `popup` | 补充说明 | 拓展知识 | `triggerText` / `popupContent` |
| `audio` | 听力 | 语言、音乐 | `src` |
| `video` | 演示 | 实验、操作 | `src` / `poster` |
| `gallery` | 观察 | 多图对比 | `images[]` |

**选型原则**：

- 要**判断** → `quiz`
- 要**先思考再对答案** → `reveal`
- 要**动手画** → `draw`
- 要**记住** → `read`
- 只是**补充** → `popup`

**不要把 quiz 当万能**：连续三个选择题会让学生疲劳，中间穿插 `reveal` 或 `draw`。

## 三·v2、自然科学互动组件（2026-09-03 新增）

用于**自然现象演示/模拟**：把抽象原理变成可点、可看、可听的现象（天气、雷电、水循环…）。
属于互动的一种；所在页建议显式标 `<!-- layout: scene-phenomenon -->`（现象演示版式，整页聚焦一个现象），
让大组件独占主体。

| 组件 | markdown 语法 | 效果 | 典型内容 |
|---|---|---|---|
| `weather` 天气切换 | `<!-- weather: 晴,多云,雷阵雨,雪 -->` | 点按钮循环切换天空背景/粒子/音效 | 三下《天气》、英语 weather、连续观察记录 |
| `storm` 雷电模拟 | `<!-- storm: 云里的电荷越聚越多，就会放电 -->` | 点云朵 → 电荷聚集 → 闪电 + 雷声 | 雷电成因、天气与安全 |
| `cycle` 现象循环 | `<!-- cycle: 水的循环：蒸发 => 凝结 => 降水 => 径流 -->` | 点"下一步"逐帧推进，每步可带一句说明 | 水循环 / 四季 / 月相 / 昼夜 / 植物生长 |

**语法规则**：

- `weather` 状态 2~6 个，用顿号/逗号分隔；状态词用常见天气词（晴 / 多云 / 阴 / 小雨 / 雷阵雨 / 雪…），渲染端按关键词自动匹配天空、表情与雨雪雷声。
- `storm` 冒号后写一句现象说明或悬念（放电后展示）。
- `cycle` 步骤用 `=>` 连接（兼容 `→` / `->`）；标题用 `：` 与首步隔开；每步 2~8 字，
  需要讲解时写 `步骤名（一句话说明）`，说明 ≤20 字。

**选型约束**：

- `storm` **只用于与雷电 / 放电 / 静电有关的内容**，禁止在非气象、非电学主题里凑数。
- `cycle` 的步骤要有**因果或时序闭环**（能回到起点），3~6 步；避免流水账罗列。
- 三组件都是"现象页主角"：该场景不要再堆 quiz / 气泡，最多一条旁白点题（≤30 字）。
- 一个科学课件最多 2~3 处这类组件：少了没"玩"，多了变"看动画"。
- 套进普通课文（语文/道法）时慎用，先用 read/reveal 等常规互动。

## 四、学段差异

| 学段 | 场景数 | 互动 | 文字 | 语气 |
|---|---|---|---|---|
| 小学低段 | 8~10 | 3~4 处，多点读/跟读 | 更少，每场景 ≤40 字 | 活泼、拟声 |
| 小学高段 | 10~12 | 3~4 处，quiz 增多 | ≤50 字 | 亲切 |
| 初中 | 10~14 | 2~3 处，quiz + draw | ≤60 字 | 理性、讲逻辑 |
| 高中 | 12~16 | 2~3 处，draw + reveal | ≤60 字 | 严谨 |

> 低年级靠**玩**驱动，高年级靠**思**驱动。同样是 quiz，
> 低年级选项要图形化有趣味，高年级选项要设置典型错误（辨析价值）。

## 五、常见问题

| 问题 | 表现 | 修正 |
|---|---|---|
| 文字堆砌 | 每页上百字、无气泡 | 改用对话推进，旁白 ≤40 字 |
| 零互动 | 全是旁白+陈述 | 每课件至少 2 处互动 |
| 互动单调 | 连续三个 quiz | 穿插 reveal / draw / read |
| PPT 化 | 出现学习目标、小结、作业页 | 改为情境场景，用对话收束 |
| 角色同质 | 三个角色说一样的话 | 给角色分工（提问/抢答/纠正） |
| 情节断裂 | 场景间无关联 | 用一条问题线串起来 |

## 六、屏幕适配（缺省要求）

**缺省目标是宽窄两个比例都自适应；若做不到，一律按「手机窄屏」设计。**

内容量按**窄屏**取上限——窄屏宽度最小，同样字数占更多行，
是更紧张的情况；按窄屏设计，宽屏自然也放得下。

### 内容侧落地（按窄屏取上限）

| 项 | 上限 | 理由 |
|---|---|---|
| 每场景总字数 | ≤60 字 | 窄屏下一行约 16~18 字，60 字 ≈ 4 行 |
| 旁白 | ≤40 字 | 窄屏约 2~3 行 |
| 气泡 | 2~4 条，每条 ≤20 字 | 窄屏每条约 1~2 行 |
| 互动选项（quiz） | 每项 **≤12 字** | 窄屏选项要放得下，超了会换行挤压 |
| 装饰 | 少而小 | 窄屏空间紧张，装饰抢地方 |

**一屏装得下的粗略算法**：标题 1 行 + 旁白 2~3 行 + 气泡 4~8 行 + 互动 2~3 行
≈ 9~15 行。窄屏一行约 30px，`480px` 高度大致到顶——**所以宁少勿多**，
宁可分两个场景，也不要一个场景塞满。

> 判断口诀：写完后按"手机竖屏"在脑子里过一遍，
> 需要往下滑才看得完的，就是超了。

## 七、校验清单（生成后自查）

- [ ] 场景数在 8~16
- [ ] 每场景总字数 ≤60
- [ ] 互动 ≥2 处，且类型不单一
- [ ] 无「学习目标」「小结」「作业」类页面
- [ ] 气泡 ≤4 条、每条 ≤20 字
- [ ] **窄屏装得下**：按手机竖屏过一遍，不需要下滑才看得完
- [ ] quiz 每个选项 ≤12 字（窄屏放得下）
- [ ] 角色有性格区分
- [ ] `themeId` 与 `mood` 已设置
- [ ] 结构符合 `types.ts` 的 `Story` / `StoryScene` 定义
