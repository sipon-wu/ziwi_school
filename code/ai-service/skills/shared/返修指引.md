# 返修指引（关卡1 未过时怎么改）

> 本文件**只在"自动校验未过、需要重修"时注入提示词**（正常生成不注入，避免白付 token）。
> 用途：把"你违规了"变成"**这里该怎么补**"——实测证明光给违规清单，模型改不对
> （"它不知道自己写的 quiz 被当成非法组件丢掉了"）。

## 总则：先判断这是「上界」还是「下界」问题

实测规律：**模型对上界（字数/数量超上限）遵守得好，对下界（数量不足）遵守得差。**
因为超了可以"删/拆"，不足却要**创作新内容**，模型倾向少写。

| 类型 | 表现 | 正确改法 |
|---|---|---|
| **上界**（超了） | 字数超标、要点 >5、气泡 >4 | **拆句 / 换版式 / 删冗余** |
| **下界**（不足） | 组件 <3 种、某页缺组件、互动 <2、页数少、items 数量不足 | **补内容**——不是改措辞，是**真的写出新的一行/一个新组件** |
| **结构** | 字段名错、把组件类型当 layout、版式名非法 | **照示例抄**，不要自己发明 |

**下界类违规禁止用"改措辞/换同义词"糊过去**——校验器数的是"条目数"，糊不过去。

## 高频违规 → 具体补法

### 1. 内容页缺 visual（本次最高频）
判据：`content-2col` / `content-grid` / `image-text` / `title-body` 这四类页**必须带且只带一个** `VISUAL_JSON` 组件
（**该页有互动的可豁免**）。

改法：**在被点名的页末尾补一行**，从下列里选一个与语义相符的（照抄字段名）：

```markdown
<!-- VISUAL_JSON:{"type":"sequence","items":[{"label":"第一步","hint":"简短说明"},{"label":"第二步","hint":"简短说明"},{"label":"第三步","hint":"简短说明"}]} -->
<!-- VISUAL_JSON:{"type":"quote","text":"一段 8~100 字的原文或关键句","from":"出处"} -->
<!-- VISUAL_JSON:{"type":"compare-table","cols":["对象甲","对象乙"],"rows":[{"label":"维度一","cells":["内容","内容"]},{"label":"维度二","cells":["内容","内容"]}]} -->
<!-- VISUAL_JSON:{"type":"structure","levels":[{"label":"根","children":["子项一","子项二"]},{"label":"枝","children":["子项一","子项二"]}]} -->
<!-- VISUAL_JSON:{"type":"annotate","text":"一段 30~180 字的分析文本，关键词要在文中真实出现","marks":["关键词一","关键词二"]} -->
```

⚠️ **不许**：把组件写到页外、写两个（只允许一个）、或把 type 写成 `layout`。

### 2. 组件多样性 < 3 种
全课 `VISUAL_JSON` 的 `type` 至少 3 种。**给已有页面换/加不同类型的组件**，
不要在已有组件上改措辞。十一种可选：
`sequence / compare-table / timeline / char-card / compare-card / quote / diagram / icon-card / structure / flow / annotate`

### 3. annotate.text 不在 30~180 字（本次高频）
`annotate` 是**长文本分析**组件，短句**不属于它**。

- 若你的 text 只有十几个字 → **不要用 annotate**，改用：
  `quote`（8~100 字原文）、`icon-card`（≤10 字标签）、`sequence`（≤16 字/项）
- 若确实需要 annotate → **把 text 写足 30 字以上**（补上分析/解释，不是凑字），
  且 `marks` 里的每个词**必须在该 text 中真实出现**。
- 实在写不长的内容 → 整块走 `title-body` 的要点，**不放组件也比放半截组件好**。

### 4. 内容页/教学页字数超标（grid 字长 / 2col 字长 / 教学页字长 / 正文超长）
按"单条字数"换版式，**不要缩字号**：

| 单条字数 | 可用版式 |
|---|---|
| ≤12 字 | `content-grid`（5~6 条） |
| 13~30 字 | `content-2col`（≤3 条）或 `title-body` |
| >30 字 | 只能 `title-body` 竖排，或**先拆成多条短句** |

### 5. 页数不足 / 版式多样性不足
- 页数少 → **补页**（补的是"可支撑 2~4 分钟讲解的具体内容"，不是加空页）
- 版式 <4 种或连续 3 页同版式 → **把其中某页换成别的版式**（按该页内容形态选，别硬换）
- 「结构页（cover/goal/summary/homework）合计 ≤4 页」——超出就把中间某页改成 `content-*`

### 6. 互动不足（< 2 处）
补**互动标记**（不是 VISUAL_JSON 的 type）：

```markdown
<!-- quiz: 问句 | 选项A | 选项B | 选项C | 正确项索引(0起) -->
<!-- reveal: 提示语 => 要揭示的内容 -->
<!-- readalong: 要跟读的句子 -->
```

### 7. 结构类（字段名错 / 非法版式 / 非法组件 / VISUAL 解码失败）
**照 `courseware-ppt/references/版式与组件选型.md` 的「完整示例」原样抄**：

- 字段名：`sequence` 是 `items[].label` / `.hint`（**不是 `text`**）；
  `char-card` 是 `chars`；`structure` 是 `levels[].children`；`flow` 是 `steps`…
- **组件类型名绝不能当 layout**（`<!-- layout: quote -->` 是错的）
- 版式名只能取受控集合；组件 `type` 只能取上列 11 种

### 8. 各组件数量下限（items/rows/nodes/chars/pairs/branches/levels/steps 个数不足）
**补足条目**，每条都写具体内容：

| 组件 | 下限 | 每项怎么写 |
|---|---|---|
| `sequence.items` | 3 | `label` 2~16 字 + `hint` ≤20 字 |
| `compare-table` | cols 2 / rows 2 | 每格必填，**严禁空格或"—"** |
| `timeline.nodes` | 3 | `label` 2~12 字 + `desc` ≤30 字 |
| `char-card.chars` | 4 | **每个字都要带拼音** |
| `compare-card.pairs` | 2 | `label` 1~6 字 + `left/right` 2~28 字 |
| `diagram.branches` | 3 | `label` ≤16 字 + `desc` ≤26 字 |
| `icon-card.items` | 3 | `label` ≤10 字 + `desc` ≤12 字 |
| `structure.levels` | 2 | 每层 `children` 2~6 项 |
| `flow.steps` | 3 | `label` ≤16 字 + `desc` ≤24 字 |
| `annotate.marks` | 2 | 每个词须在 `text` 中真实出现 |

### 9. 占位符 / 教师视角 / 目标空话
- 占位符（"待补充""XXX""占位"）→ **换成真实内容**，写不出就删掉该条
- "教师引导学生…" → 改成"**学生将看到/学会什么**"
- "会认会写 N 个生字" → 列出**具体是哪几个字**
