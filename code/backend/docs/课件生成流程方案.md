# 课件生成流程方案（教案驱动 · 生成式）

> 目标：建立**可复用**的课件生产流水线，取代手工撰写课件内容。
> 核心原则：**课件由教案派生，提示词由 AI 生成，内容由技能生成，质量由关卡把控**。
> 阶段一：在 CodeBuddy 内验证流程；阶段二：平台接入百炼 + 小微 AI，支持用户互动生成。

---

## 0. 为什么要换流程（现状问题）

| 现状 | 问题 |
|------|------|
| 课件内容手工编写（seed 里硬编码提纲） | 12 套已耗时巨大，无法扩展到全部学科/年级 |
| 内容与教案无关联 | 课件与教案可能不一致，教学目标覆盖无法保证 |
| 质量靠人眼发现 | "占位符泄漏""字号没层级"等问题反复出现 |
| 无法支持用户自定义生成 | 教师想生成自己课的课件时，没有可用链路 |

**新流程的本质**：把"人写内容"变成"人定规范 + AI 依教案生成 + 关卡质检"。

---

## 1. 流程总览（6 阶段流水线）

```
┌─ S0 需求澄清（小微主导）★ 新增 ───────────────┐
│ 输入：用户请求（可能无教案）                   │
│ 处理：校验「课件生成条件」，缺失则提问补全     │
│ 输出：课件规格书 CoursewareSpec               │
└──────────────┬──────────────────────────────┘
               ▼
┌─ S1 教案解析 ────────────────────────────────┐
│ 输入：LessonPlan（若有）或 S0 规格书          │
│ 处理：结构化提取（规则解析 + AI 补全）         │
│ 输出：教案结构 JSON                           │
└──────────────┬──────────────────────────────┘
               ▼
┌─ S2 提示词生成（小微 / AI）───────────────────┐
│ 输入：教案结构 + 课件宪法 + 学段课时规则 + 模板 │
│ 处理：AI 将教案转译为课件生成提示词            │
│ 输出：生成提示词（页面规划 + 组件 + 素材 + 互动）│
└──────────────┬──────────────────────────────┘
               ▼
┌─ S3 课件生成（PPTX 技能 / 百炼）──────────────┐
│ 输入：提示词 + 模板 + 素材库                   │
│ 处理：生成课件内容（页面 + 可视化组件 + 版式）  │
│ 输出：课件内容（Markdown + VISUAL 组件）       │
└──────────────┬──────────────────────────────┘
               ▼
┌─ S4 质量检验（三道关卡）──────────────────────┐
│ 关卡1：自动规则校验                            │
│ 关卡2：AI 内容评审                             │
│ 关卡3：视觉检查（subagent 看图）               │
│ 输出：质检报告（通过 / 问题清单）              │
└──────────────┬──────────────────────────────┘
               ▼  不通过则回退重试（限次）
┌─ S5 交付入库 ────────────────────────────────┐
│ 入库（materials）→ 可编辑 → 可导出（PPTX/PDF） │
└──────────────────────────────────────────────┘
```

## 2. 各环节详细设计与质量要求

### S0 需求澄清（小微主导）★ 课标对齐的守门环节

**背景**：用户未必有教案，也可能只给一句模糊需求（如"帮我做个《观潮》课件"）。
若直接生成，AI 会基于模糊需求产出"看着像样，但课标不对齐、课时不匹配、学段不适配"的内容——
即**会话式无效产出**：对话流畅、内容完整，实际却不可用。这是 AI 生成内容的典型失败模式。

因此课件生成前必须先满足**生成条件**（必要输入条件）：
- 满足 → 进入生成
- 不满足 → 小微向用户提问，直至满足（或按降级策略处理）

**生成条件是防止"会话式无效产出"的闸门**——宁可多问一轮，也不产出不可用的课件。

#### 课件生成条件（最小必要信息集）

| 层级 | 字段 | 缺失时的处理 |
|------|------|-------------|
| **必需** | 学科 | **必须询问**（决定学段适配/组件选型/语言难度） |
| **必需** | 年级 | **必须询问**（同上） |
| **必需** | 课题/主题 | **必须询问**（决定生成什么） |
| **必需** | 课时（分钟） | **必须询问**（决定页数与内容密度），可给默认值 |
| **强需** | 教学目标 | 从知识点库/课标库**推断** → 向用户确认 |
| **强需** | 教学重难点 | 从知识点库/课标库**推断** → 向用户确认 |
| **可选** | 教材版本/单元 | 推断即可，不阻塞生成 |
| **可选** | 风格偏好 | 按学科推荐默认值 |

#### 无教案时如何"对齐课标"

关键认知：**"无教案" ≠ "无依据"**。平台已有知识点库与课标库，可反查：

```
课题 + 学科 + 年级 + (版本) + (单元)
   → 查知识点库 KnowledgeNodes
   → 查课标库 CurriculumAlign
   → 推断教学目标 / 重难点
   → 向用户确认（而非凭空生成）
```

因此即便用户没有任何教案，课标对齐依然可达成——**前提是问清楚学科/年级/课题**。

#### 提问机制设计（避免挤牙膏）

| 原则 | 做法 |
|------|------|
| **一次问完** | 缺失项合并为一轮提问，不一问一答 |
| **带推断与默认值** | "我查到四年级语文有《观潮》一课，30 分钟课时，对吗？" 优于 "请问几年级？" |
| **确认优于开放提问** | 展示推断让用户确认，比让用户从零回答成本低 |
| **限制轮次** | 最多 2-3 轮；超出则降级 |
| **可降级** | 用户答不上来/不愿答 → 按最佳实践生成，**标注"目标为系统推断，待确认"** |

#### 输出：课件规格书 `CoursewareSpec`

```json
{
  "subject": "语文", "grade": "四年级", "title": "观潮",
  "period_minutes": 30,
  "objectives": ["认识12个生字…", "..."],
  "key_points": ["按顺序观察的方法"],
  "difficulties": ["体会潮来时的壮观描写"],
  "knowledge_nodes": ["kn_001"],
  "curriculum_align": ["课标条目…"],
  "source": "lesson_plan:lp_xxx | user_input | inferred",
  "pending_confirm": []          // 需用户确认的推断项
}
```

**质量关卡（S0-QC）**：
- 必需字段（学科/年级/课题/课时）全部齐备 → 放行进入 S1
- 任一必需字段缺失 → 继续提问（≤3 轮）
- 3 轮后仍缺失 → 中止并说明原因，或按默认值生成并全部标记 `pending_confirm`

### S1 教案解析

**输入**：`LessonPlan` 记录（若有）或 S0 产出的 `CoursewareSpec`
- `Content`（教案正文 Markdown：教学目标 / 重难点 / 教学过程 / 板书 / 作业）
- 元数据：`Subject`、`Grade`、`Title`、`Unit`、`LessonPeriod`、`KnowledgeNodes`、`CurriculumAlign`

**处理**：
1. 规则解析 `Content`：按 `##` 分节提取「教学目标」「重难点」「教学过程」「作业」
2. AI 补全缺失字段（如教案未分节，用 LLM 结构化）

**输出**：教案结构 JSON
```json
{
  "subject": "语文", "grade": "四年级", "title": "观潮",
  "period_minutes": 30,
  "unit": "第一单元",
  "objectives": ["认识12个生字…", "有感情朗读…", "..."],
  "key_points": ["按顺序观察的方法"],
  "difficulties": ["体会潮来时的壮观描写"],
  "stages": [
    {"name": "情境导入", "minutes": 3, "activity": "播放大潮视频，提问"},
    {"name": "初读感知", "minutes": 5, "activity": "朗读，梳理脉络"},
    {"name": "精读品析", "minutes": 15, "activity": "品读潮来时的描写"}
  ],
  "knowledge_nodes": ["kn_001", "kn_002"],
  "homework": {"basic": "...", "advanced": "..."}
}
```

**质量关卡（S1-QC）**：

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 必填完整性 | 目标≥3 条、重难点≥1、环节≥3、课时>0 | AI 补全；仍缺 → **阻断**，提示教师完善教案 |
| 环节时长合理 | 各环节 minutes 之和 ≈ 总课时（误差 ≤20%） | 按课时比例自动归一化 |
| 知识点非空 | knowledge_nodes ≥1 | 从 Unit/Subject 推断；仍空 → 告警但继续 |
| 学段学科合法 | Subject/Grade 在系统枚举内 | **阻断**（无法选模板/组件） |

### S2 提示词生成（小微 / AI）★ 核心环节

**设计要点**：提示词**不是人写的**，而是 AI 依据「教案结构 + 课件宪法 + 规则库」自动生成。

**输入**：
1. S1 教案结构 JSON
2. **课件宪法**（生成规范，见第 3 节）
3. 学段课时规则表（见下）
4. 可用组件清单与模板风格

**学段课时规则表**（驱动页数与密度）：

| 课时 | 建议页数 | 每页承载 |
|------|---------|---------|
| 20 分钟 | 8-10 页 | 2-2.5 分钟/页 |
| 30 分钟 | 12-14 页 | 2-2.5 分钟/页 |
| 40-45 分钟 | 14-16 页 | 3 分钟/页 |

**组件选型规则**（驱动"知识结构化"）：

| 教案内容特征 | 推荐组件 |
|-------------|---------|
| 顺序/阶段（如潮来前→潮来时→潮头过后） | `timeline` |
| 递进/程度变化（如声音由小到大） | `sequence` |
| 多维度对比（如三阶段的样子/声音） | `compare-table` |
| 并列知识条目（如生字表） | `char-card` / grid |
| 易混辨析（如多音字） | `compare-card` |
| 原文重点句 | `quote` |

**输出**：生成提示词（结构化）
```json
{
  "lesson_ref": {"subject":"语文","grade":"四年级","title":"观潮","minutes":30},
  "page_plan": [
    {"idx":1,"title":"封面","layout":"edu-cover","component":null},
    {"idx":2,"title":"这节课我要学会什么","layout":"edu-goal","component":null},
    {"idx":6,"title":"课文脉络","layout":"blank","component":{"type":"timeline","nodes":[…]}},
    {"idx":8,"title":"潮来时","layout":"blank","component":{"type":"sequence","items":[…]}}
  ],
  "style": "china",
  "theme_id": "zgf-ink-wash",
  "interactions": [{"page":4,"type":"点读"},{"page":13,"type":"角色扮演"}],
  "assets_needed": [{"page":1,"type":"image","desc":"钱塘江大潮全景"}]
}
```

**质量关卡（S2-QC）**：

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 目标全覆盖 | 教案每条 objective 至少映射到 1 页 | AI 补页；最多重试 2 次 |
| 重难点突出 | 重难点所在环节占页数比例最高 | 调整页面分配 |
| 页数课时匹配 | 页数落在课时规则区间内 | 增删页面至合规 |
| 组件选型合理 | 顺序→timeline、对比→table、递进→sequence | 按规则表校正 |
| 互动达标 | 每课 ≥2 处互动；低学段 ≥3 处 | 补充互动点 |
| 符合宪法 | 学生视角 / 目标具体化 / 零占位符等 8 条 | 按宪法重写提示词 |

### S3 课件生成（PPTX 技能 / 百炼）

**输入**：S2 提示词 + 模板（pptThemes）+ 素材库（materials）

**处理**：
- 阶段一（CodeBuddy 验证）：用 **PPTX 技能**（pptxgenjs）按提示词生成
- 阶段二（平台化）：调用**百炼**大模型生成结构化内容，再渲染

**输出**：课件内容
- Markdown 提纲（`## 页标题` + `- 要点`）
- 每页 `<!-- layout: xxx -->`
- 每页可选 `<!-- VISUAL:base64 -->` 可视化组件
- 素材引用

**质量关卡（S3-QC，自动规则）**：

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 结构合法 | layout 在白名单内；每页均有 layout | 回落 `title-body` + 告警 |
| 组件合法 | VISUAL JSON 通过 `isValidVisual` | 丢弃非法组件 + 告警 |
| 页数一致 | 实际页数 = 提示词 page_plan 页数（±1） | 重新生成 |
| 素材可达 | 引用的素材 ID 在库中存在 | 降级为矢量占位图形并标记 |
| 编码正确 | base64 可解码，中文无乱码 | 重新编码 |

### S4 质量检验（三道关卡）★ 质量守门

#### 关卡1：自动规则校验（零成本，每次必跑）

| 检查项 | 判定 |
|--------|------|
| 零占位符 | 无"思维导图占位""待补充""XXX""标题"等 |
| 页数范围 | 在课时规则区间 |
| 每页有内容 | 每页要点≥2 或 有可视化组件 |
| 版式合法 | 全部 layout 在白名单 |
| 组件合法 | 全部 VISUAL 通过校验 |
| 字数合理 | 单页正文 ≤120 字（避免堆砌） |
| 编码 | 无乱码、base64 正确 |

#### 关卡2：AI 内容评审（用 LLM 评分）

评审维度（每项 1-5 分，≥4 为通过）：

| 维度 | 评审要点 |
|------|---------|
| 教案一致性 | 课件内容是否忠实反映教案目标与重难点 |
| 知识准确性 | 概念、原文、生字、公式是否正确 |
| 学段适配 | 语言难度、认知水平、趣味性是否符合该年级 |
| 目标覆盖 | 教学目标是否都被课件承载 |
| 课时匹配 | 内容量是否撑得起课时 |
| 趣味性 | 互动/游戏/情境是否充分 |
| 学生视角 | 是否出现"教师引导学生…"等教案语言 |

**不通过**：生成问题清单 → 回退 S3 重新生成（最多 3 次）→ 仍不通过则标记**待人工**

#### 关卡3：视觉检查（subagent 看图）★ 解决"差感觉"

**流程**（严格按 PPTX 技能规范）：
1. 导出 PPTX → 转 PDF → 转图片（每页一张）
2. **交给 subagent 检查**（不能用生成者的眼睛自查）
3. subagent 报告问题 → 修复 → 重新导出验证 → 循环至无新问题

**检查清单**：
- 元素重叠（文字压形状、线穿过字）
- 文字溢出/被裁切
- 间距不均（某处大片空白、某处拥挤）
- 边距不足（距边缘 <0.5"）
- 对齐不一致
- 低对比度文字/图标
- 文字过窄导致过度折行
- **字号层级**：标题 ≥ 正文的 1.8 倍
- **视觉元素**：每页至少一个视觉主体（图/表/组件），无纯文字页
- 残留占位内容

### S4 补充：课件广度与深度的最低要求

生成条件（S0）约束**输入**，本节约束**输出**——防止出现"覆盖不全"或"浮于表面"的课件。
每个维度均需**可量化、可校验**，避免流于主观判断。

#### A. 广度（覆盖面：该讲的都讲了吗）

| # | 维度 | 量化指标 | 最低要求 | 校验方式 |
|---|------|---------|---------|---------|
| B1 | **目标覆盖度** | 课件承载的目标数 / 教案（或课标）目标总数 | **100%** | 自动（目标→页面映射） |
| B2 | **知识点覆盖度** | 课件覆盖的知识点数 / 选定知识点总数 | **≥90%** | 自动（知识点→页面标注） |
| B3 | **环节完整性** | 必需环节齐备率（导入/新授/巩固/小结/作业） | **100%** | 自动（版式+标题识别） |
| B4 | **课标对齐度** | 关联上的课标条目数 / 应关联条目数 | **100%** | 半自动（课标库匹配） |

#### B. 深度（质量：讲到什么程度）

| # | 维度 | 量化指标 | 最低要求 | 校验方式 |
|---|------|---------|---------|---------|
| D1 | **内容具体度** | 含"具体知识载体"的页占比（生字表/公式/原文/例题数据/实验步骤） | **≥50%** | 半自动 + AI 评审 |
| D2 | **例证充分性** | 关键知识点配有实例/例题的比例 | **≥80%** | AI 评审 |
| D3 | **认知层次** | 覆盖布鲁姆层次数（识记→理解→应用→分析→评价→创造） | **≥3 层**，且须含"理解"以上 | AI 评审 |
| D4 | **巩固检测** | 练习 / 检测 / 探究类页面占比 | **≥10%** | 自动（版式+标题识别） |

#### C. 结构约束（承载广深，不足则广深无从落地）

| # | 维度 | 量化指标 | 最低要求 | 校验方式 |
|---|------|---------|---------|---------|
| S1 | **课时密度** | 实际页数 vs 课时推导页数 | 落在区间内（如 30 分钟 → 12-14 页） | 自动 |
| S2 | **可视化程度** | 含可视化组件（非纯文字）的页占比 | **≥60%** | 自动 |

#### D. 学段差异化（同一维度，不同学段不同阈值）

| 维度 | 小学低段（1-3） | 小学中高段（4-6） | 初中 | 高中 |
|------|----------------|------------------|------|------|
| 互动点数 | ≥4 | ≥3 | ≥2 | ≥2 |
| 单页文字量 | 更少（图为主） | 适中 | 适中 | 可更密 |
| 认知层次要求 | ≥2 层 | ≥3 层 | ≥3 层（含分析） | ≥4 层（含分析/评价） |
| 可视化占比 | ≥70% | ≥60% | ≥50% | ≥40% |

#### E. 判定与处理

| 指标类型 | 未达标处理 |
|---------|-----------|
| **硬指标**（B1/B3/S1 及必需字段） | **拦截**，回退 S2/S3 重新生成 |
| **软指标**（B2/D1-D4/S2） | 记录问题，累计 ≥2 项未达标则返工；单项轻微不足可放行并标注 |

> 设计要点：广度指标优先用**自动校验**（可映射、可计数），深度指标用 **AI 评审**（需语义理解）。
> 广度"缺了"容易发现且必须补齐；深度"浅了"需判断是否影响教学，故给一定容忍度。

### S5 交付入库

| 动作 | 质量要求 |
|------|---------|
| 入库 materials | 必带 `school_id`、`user_id`（避免列表不可见——已知历史缺陷） |
| 绑定教案 | 记录来源教案 ID，支持"课件-教案"双向追溯 |
| 编辑器可打开 | 平台编辑器加载无报错，页面数与生成一致 |
| 导出一致 | PPTX/PDF 导出内容与预览一致，组件完整 |
| 可追溯 | 记录生成提示词、模型版本、质检报告 |

## 3. 课件宪法（S2 的规范输入）

已写入 `ai-service/api_server.py` 的 `structure_hint`，作为提示词生成的硬约束：

1. **学生视角**：写"学生将看到/学会什么"，禁止"教师引导学生…""教师点拨…"
2. **目标具体化**：禁止"会认会写 N 个生字"，必须列出是哪 N 个字
3. **引用真实内容**：文科出原文金句+生字表；理科出公式+例题数据
4. **趣味按学段**：低段游戏/竞赛/角色扮演；中段情境/探究；高段问题链/辩论/实验；每课≥2 处互动
5. **时长匹配**：每页支撑 2-4 分钟
6. **零占位符**：禁止"思维导图占位""待补充"
7. **版式服从内容**：grid 放并列、table 放对比、sequence 放递进、image-text 放图文
8. **教案章节不单独成页**："教学重难点""板书设计"融入内容页

**补充视觉宪法**（来自 PPTX 技能，纳入 S4 关卡3）：
- 字号层级：组件标题 7mm / 主文字 5.5mm / 辅助 3.8mm / 生字 14mm
- 每页至少一个视觉主体，无纯文字页
- 标题与正文字号差 ≥1.8 倍
- 正文左对齐，仅标题居中

## 4. 两阶段落地路径

### 阶段一：CodeBuddy 内验证流程（当前）

| 步骤 | 动作 | 验证标准 |
|------|------|---------|
| 1 | 准备教案源：为 12 套种子课件各准备/生成一份教案 | 教案结构 JSON 通过 S1-QC |
| 2 | 用 AI 依教案生成提示词 | 提示词通过 S2-QC（目标全覆盖、页数匹配） |
| 3 | 用 PPTX 技能按提示词生成课件 | 通过 S3-QC（结构合法、组件合法） |
| 4 | 跑三道质检关卡 | 关卡1 全过；关卡2 各项≥4 分；关卡3 subagent 无阻塞问题 |
| 5 | 入库 + 浏览器验收 | 列表可见、编辑器可打开、导出 PPTX 与预览一致 |

**产出**：12 套种子课件 + **可复用的流程脚本**（S1-S5 各环节可重跑）

### 阶段二：平台化（后续）

| 能力 | 实现 |
|------|------|
| 教案驱动 | 教师选教案 → 一键生成课件 |
| 小微互动 | 用户提供需求（"多加些互动""讲得再细点"）→ 小微调整提示词 → 重新生成 |
| 百炼接入 | S2/S3 调用百炼大模型，替代本地生成 |
| 用户介入 | 教师可在任意环节修改提示词/页面/组件，重新生成或手工微调 |
| 质检内建 | S4 关卡作为平台能力，生成后自动出质检报告 |

## 6. 关键设计决策与风险

| 决策 | 理由 | 风险与对策 |
|------|------|-----------|
| 课件由教案派生 | 保证目标覆盖与一致性 | 教案质量差 → 课件差；对策：S1-QC 阻断劣质教案 |
| 提示词由 AI 生成 | 可扩展到任意学科/年级 | 提示词质量波动；对策：S2-QC + 重试 |
| 用技能生成而非手搓 | 可扩展、可批量 | 生成结果需严格质检；对策：三道关卡 |
| 视觉检查用 subagent | 避免"自己看自己写的"盲区 | 增加耗时；对策：仅对不通过或抽样的页面执行 |
| 阶段一先验证流程 | 降低平台化风险 | —— |

## 7. 待确认事项

1. **教案来源**：12 套种子课件是先由 AI 生成教案，还是使用平台现有教案库？
2. **素材**：课件所需图片/视频是否有素材库可用，还是先用矢量占位图形？
3. **验收标准**：关卡2 各项 ≥4 分是否合适，还是部分项（如知识准确性）要求 ≥4.5？
4. **范围**：阶段一是先跑 1-2 套验证流程，还是直接跑完 12 套？
