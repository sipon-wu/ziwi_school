# 课件生成 · 执行计划与执行约定

> 配套：`课件生成Skills架构方案.md` / `课件视觉资产架构方案.md` / `风格提示词库方案.md`
> 本文件回答两件事：**做什么（计划）** 与 **怎么保证不跑偏（约定）**。

---

# 第一部分：执行约定（防跑偏）

## 约定 0 · 最高纪律（2026-08-31 确立，优先于以下所有约定）

> **课件只能由 Skill 生成。CodeBuddy 只做提示词，不做渲染。**

1. **唯一生成路径**：课件一律由 Skill 产出。本地预生成种子课件、服务器上为用户提供
   的生成服务，**两条链路走同一套 Skill**，不得各写一套 prompt。
2. **PPT 与 H5 各用专用 Skill**：`courseware-ppt` 与 `courseware-h5` 是两个 Skill，
   产物形态不同（PPT = markdown + VISUAL；H5 = Story 场景分镜），**不可混用**。
3. **CodeBuddy 不做任何渲染**：不得编写渲染脚本，不得生成 pptx / html 渲染产物。
   渲染由平台渲染器负责（PPT：`PptxPreview` / `exportPptx`；H5：`buildStoryH5`）。
4. **渲染相关的调整，一律通过提示词向 Skill 提出**：如"表格撑破""装饰位置不对"，
   应改提示词让 Skill 输出合规内容，**而不是 CodeBuddy 去改渲染器或手工修产物**。
5. **CodeBuddy 的工作边界**：提示词 + 提示词优化 + 素材库/工具 + 校验规则。仅此。

> 违反此纪律的后果（2026-08-31 已实际发生）：手工产物与 Skill 产物混淆、
> 用户在 staging 反复看到旧版本、以及一整天的返工。

---

> 前两轮执行出现两次方向性偏离，约定由此而来。**动工前先对照，不是事后检查。**

## 已发生的偏离与根因

| # | 偏离 | 根因 |
|---|---|---|
| 1 | 扎进渲染层改边框/装饰，而真实诉求是生成质量 | 把"架构建设"当成了目标，忘了"解决可见问题" |
| 2 | 去改 Python 硬编码 prompt，而方案要的是 Skill | 凭惯性改现有代码，动工前没对照方案 |
| 3 | 用「限制字数」迁就糟糕容器结构 | 预设 Skill 不行；实际它自带排版能力，天然无此问题 |
| 4 | 引入「色槽」等自造抽象 | 能用一句话说清的事，起了术语名，把简单问题复杂化 |

## 约定 A · 开工三问（每步动工前自答，答不出就停下对齐）

1. **这一步让用户看到什么变化？**
   → 答不出可见产出 = 架构自嗨，**停**。
2. **它对应方案的哪一条？**
   → 对不上任何一条 = 跑偏，**停**。
3. **是在正确的层解决吗？**
   → 生成问题在生成层、渲染问题在渲染层。跨层兜底 = **停**。

## 约定 B · 层级纪律

- **生成质量问题，禁止用渲染层兜底解决。** 渲染层只负责"按 StyleDNA 执行"，不得内置业务规则。
- 内容该不该拆、多少字、几页 → 生成层（Skill + 提示词）
- 字多大、间距多少、怎么画 → 渲染层（按 StyleDNA）

> 违反此条的历史代价：为避免字密而在渲染层加降级、加截断、加字数校验，三层补丁都没治本。

## 约定 C · 先探测，后约束

- **不预设 Skill 缺什么能力。** 先让它跑，看它缺什么，再决定约束什么。
- 欲加任何约束前自问：**这个能力 Skill 是不是本来就有？**
- 若 Skill 已具备，我们再加约束 = 干扰，且浪费 token。

## 约定 D · 单一事实源

- 领域知识（宪法 / 选型规则 / 风格语义）**只维护在 Skill 的 `references/` 与 `styles/`**。
- 代码只保留执行逻辑（输出格式、JSON schema、机器校验）。
- 代码里引用 Skill 规则处，**必须写注释指向具体文件与章节**，避免两处失联。

## 约定 E · 抽象克制

- 引入新概念前自问：**不引入它能不能解决？**
- 能用一句话说清的，不起术语名。
- 已废弃的抽象：色槽（改为"资产不存颜色，颜色由 StyleDNA 给"）。

## 约定 F · 阶段验收

- 每阶段必须产出**可见产物 + 量化验证**，验证不过不进下一阶段。
- 验收看**用户视角的效果**（打开看、对比看），不只看代码跑通。

## 约定 G · 偏离申报

- 执行中发现方案有问题、或需要偏离计划，**先说明理由并获确认**，不得擅自改向。
- 宁可停下来问一次，不要跑两天再被纠正。

# 第二部分：前序工作清算

动工前先交代旧账，避免背着包袱前进。

| 前序工作 | 处置 | 理由 |
|---|---|---|
| 四份 schema（StyleDNA / DecorAsset / StructureSpec / AssetFeedback） | **保留** | 与现思路一致；StyleDNA 与提示词方案的快照层对应 |
| 装饰资产库 `visualAsset/` | **改造** | 去掉颜色，只存形状；改为按风格+位置可检索 |
| H5 渲染器参数化装饰 | **保留** | 渲染层本就应按参数执行 |
| 小微焦点感知 | **保留** | 闭环的输入端，仍需要 |
| 脚本从 Skill 加载规则 | **保留** | 单一事实源，已落地 |
| **版式×字长补丁**（单条≤12字等） | **废弃** | Skill 自带排版能力，天然无字密问题；限制内容是错误的解法 |
| **compare-table 填满校验** | **保留** | 属内容完整性，非视觉，仍有效 |
| 渲染层"打破框线"改造 | **暂缓** | 未被验证为用户可见痛点，按约定 A 应后置 |

# 第三部分：阶段计划

> 排序原则：**先备粮草，再定契约，后验证，最后闭环。**

## P0 · 素材准备（Skill 的粮草）

素材不全就接管，Skill 只能现造 → 又回到浪费 token。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P0-1 | 风格提示词库 | `styles/` 下 3~5 条（语义 + 场景×学段适配矩阵） | 一条完整样例过目确认颗粒度 |
| P0-2 | 版式库索引 | 11 类组件的 ID + 适用场景，**供 Skill 检索** | 能按语义检索到组件 |
| P0-3 | 装饰资产库 | 形状集合，**不含颜色**，按风格+位置可检索 | 一份资产能用于多种风格 |
| P0-4 | 学科组件 | 田字格 / 数轴 / 坐标系 | 可后置，第一版留接口 |

## P1 · Skill 契约

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P1-1 | 输出契约 | 结构化内容 + 资产引用 + StyleDNA 快照 | 装饰引用中无裸色值 |
| P1-2 | SKILL.md 更新 | SOP + 契约 + 工具定义（template.query / asset.search） | Skill 能被完整执行 |

## P2 · 生成验证

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P2-1 | 生成《函数》完整课件 | 12~15 页 | 与手搓版对比质量 |
| P2-2 | 变量对照 | 同风格换学段、同学段换场景 | 风格跟随生效，且分寸合理 |
| P2-3 | token 计量 | 与"现造素材"方案对比 | 量化省幅 |

## P3 · 闭环

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P3-1 | 反馈采集 | 结构化反馈入池（区分通病/偏好/个案） | 偏好不污染全局 |
| P3-2 | 命中率统计 | 按 风格×场景×学段 分组 | 低命中组合可识别 |
| P3-3 | 校准引擎 | 达阈值修正适配值（迟滞 + k-anonymity） | 模拟反馈能收敛 |

# 第四部分：本轮待确认

## 附：一句话总纲

> **我们提要求、给素材；Skill 自行发挥产出内容并快照 StyleDNA；渲染层只管按 StyleDNA 执行。**
> 好看靠语义与分寸，省时靠素材与经验复用，省 token 靠引用而非生成。
