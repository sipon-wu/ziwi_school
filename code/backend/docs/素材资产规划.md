# 素材资产规划

> 定位：**素材库要建哪些资产**的清单、格式策略与标记规范。
> 配套：`风格提示词库方案.md`（如何被选用与进化）、`课件生成Skills架构方案.md`（引用而非生成）

---

## 一、总原则

| 原则 | 说明 |
|---|---|
| **不排斥任何格式** | SVG / PNG / GIF 各有优势，按用途选择，不搞一刀切 |
| **能外采不外造** | Lucide（ISC）/ Tabler（MIT）可商用、免署名 |
| **找不到才手搓** | 学科组件、中国风等开源库无覆盖 |
| **位图靠标记管控** | 位图不可着色，因此必须标清**色彩系 + 适用场景 + 学段**，由匹配度决定是否可用 |
| **参数优先** | 格子/刻度类用参数生成（尺寸、线宽、数量），不存死图 |

---

## 二、格式策略：各司其职

| 格式 | 优势 | 短板 | 适用 |
|---|---|---|---|
| **svg-mono**（单色 SVG） | 可着色、跨风格复用、体积小 | 表现力弱 | 学科组件、通用图标、需跟随风格的装饰 |
| **svg-color** | 矢量、可缩放、有色彩 | 不可着色 | 有固定配色的图形 |
| **PNG** | 表现力强、透明叠加 | 不可着色、体积大 | 卡通形象、纹理材质、水墨印章 |
| **GIF** | 动效、吸引注意力 | 体积大、PPT 端静态化 | 低年级互动、情境动画 |

> **GIF 在 PPT 端取首帧静态化**；H5 端完整播放。此限制须在元数据标注。

### 分配建议

| 类别 | 主用格式 | 理由 |
|---|---|---|
| 学科组件（田字格/数轴/坐标系） | svg-mono + 参数生成 | 必须跨风格复用、可着色、尺寸可调 |
| 通用图标 | svg-mono | 必须可着色 |
| **装饰资产** | **PNG/GIF 为主**，svg-mono 为辅 | 生动优先，靠色系标记管控 |
| 中国风（水墨/印章/窗棂） | PNG | 位图质感明显更好 |

## 三、位图的管控机制：标记即契约

位图不可着色，所以**能否使用完全取决于标记是否准确**。

### 必标字段

```yaml
format: png | gif | svg-color | svg-mono
colorFamily:
  色相: green | blue | warm | red | purple | neutral
  明度: light | medium | dark
  饱和度: vivid | muted | mono
scene:     [公开课, 导入课, 新授课, ...]     # 适用场景
grade:     [小学低段, 小学高段, 初中, 高中]   # 适用学段
styleFit:  [forest, cartoon, ...]            # 风格倾向
mood:      lively | calm | formal            # 情绪基调
```

### 色系匹配度

匹配度模型新增一维——**色系匹配度**：

| 素材类型 | 色系匹配度 | 说明 |
|---|---|---|
| svg-mono | **1.0（恒定）** | 可着色，适应任何 styleDNA |
| 位图 | `相似度(素材色系, styleDNA 目标色系)` | 绿意位图配森林风=高分配极简风=低分 |

于是「不可着色」不再是缺陷，而成为**匹配度的一个维度**：
色系匹配的位图照样可用，不匹配的自动被候选集过滤掉，不会串味。

> 这也让位图纳入了「匹配度进化」——若某位图在某风格下反复被删除，
> 其 `styleFit` 会被下调，此后不再推荐给该风格。

## 四、资产清单

### 4.1 装饰资产（营造氛围，与风格绑定）

| 风格 | 母题 | 建议格式 | 来源 |
|---|---|---|---|
| **forest** 森林童趣 | 叶片、树、花草、蘑菇、瓢虫、太阳、藤蔓、光斑 | PNG 为主 | 外采 + 手搓藤蔓/光斑 |
| **cartoon** 卡通 | 星星、云朵、笑脸、气球、彩虹、卡通形象 | **PNG / GIF** | 外采 + 手搓形象 |
| **china** 中国风 | 云纹、窗棂、水墨、印章、竹 | **PNG** | **全部手搓**（开源无覆盖） |
| **minimal** 极简 | 点、细线、圆、斜线、点阵 | svg-mono | 外采 |
| **academic** 严谨 | 书、尺规、徽章、分隔线 | svg-mono | 外采 |
| **tech** 科技 | 电路、网格、节点、数据流 | svg-mono / GIF | 外采 + 手搓光效 |
| **fresh** 清新 | 水滴、叶、气泡、阳光 | PNG | 外采 + 手搓气泡 |
| **flat** 扁平 | 几何色块、三角、圆 | svg-mono | 外采 |
| **business** 商务 | 图表、箭头、文档 | svg-mono | 外采 |
| **basic** 通用 | 圆点、方块、线 | svg-mono | 外采 |

### 4.2 学科组件（功能性，svg-mono + 参数生成）

| 学科 | 组件 | 复杂度 |
|---|---|---|
| 语文 | 田字格、米字格、九宫格、回宫格、拼音格、作文格、四线三格 | 低 |
| 数学 | 数轴、平面直角坐标系、几何图形、韦恩图、竖式框、分数线 | 中 |
| 英语 | 四线三格（与拼音格同源） | 低 |
| 音乐 | 五线谱 | 中 |
| 科学 | 实验器材（烧杯/试管/天平/显微镜）、电路符号 | 中 |
| 通用 | 时间轴、流程节点、对比框、标注气泡 | 低 |

> 这些**必须 svg-mono**：要跨全部风格复用、要按 styleDNA 着色、要按需求调尺寸。
> 且多为「网格 + 线条」，参数化生成优于存死图。

### 4.3 通用图标（svg-mono，外采）

箭头、勾叉、序号圆标、问号、灯泡、旗帜、时钟、对话气泡、放大镜、星标、引用标记

→ Lucide 全覆盖，直接外采。

## 六、元数据模板（统一）

```ts
{
  id: 'leaf-sprig',
  name: '草叶',
  format: 'png',                 // svg-mono | svg-color | png | gif
  category: 'decor',             // decor | subject | icon

  // ── 位图必填：色系与适用标记 ──
  colorFamily: { hue: 'green', lightness: 'medium', saturation: 'muted' },
  scene: ['公开课', '导入课', '新授课'],
  grade: ['小学低段', '小学高段'],
  styleFit: ['forest', 'fresh'],
  mood: 'calm',

  // ── 通用 ──
  tier: 1,                       // 0=原生可绘(PPT可编辑) 1=需转图
  pptBehavior: 'static',         // gif 在 PPT 取首帧
  params: { count: {...}, scale: {...}, opacity: {...} },
  defaultsByStyle: { forest: { count: 2 } },   // 匹配度进化对象
  render: 'file' | 'generated',
}
```

## 七、候选集：需要量 × 3

> **给 Skill 的是「选项」，不是「素材库」。** 素材库再大，注入 prompt 的永远只是一小撮候选。

### 7.1 大小原则

```
候选集大小 = 实际需要量 × 3
```

| 给多少 | 后果 |
|---|---|
| = 需要量 | Skill 没得选，丧失发挥空间，退化成填空题 |
| 全库（2000+） | prompt 爆炸，等于没筛选，还会诱导自造 |
| **需要量 × 3** | 够选、可控、token 可承受 |

### 7.2 需要量估算

| 类别 | 每页需要量 | 依据 |
|---|---|---|
| 装饰 `decor` | 0~3 | 由场景的装饰强度决定（练习课 0，公开课可达 3） |
| 通用图标 `icon` | 0~5 | 由页面元素决定（序号、勾叉、提示等） |
| 学科组件 `subject` | 0~1 | 一页一个核心组件 |

### 7.3 候选怎么选出来

平台按**匹配度**降序取 top N，而非随机或全量：

```
全库 → 按上下文过滤（风格/场景/学段/学科）
     → 按匹配度降序排序
     → 取 需要量 × 3
     → 注入 prompt
```

匹配度排序初值（无数据时按先验，有数据后由反馈修正）：

| 信号 | 权重 |
|---|---|
| `styleFit` 命中当前风格 | +0.4 |
| `scene` 命中当前场景 | +0.2 |
| `grade` 命中当前学段 | +0.2 |
| `subject` 命中当前学科 | +0.2 |
| 具备当前风格偏好的画法变体 | +0.1 |

**排序本身就是推荐**：匹配度高的排前面，Skill 大概率选前面的；
它若总选靠后的，说明前面的不合适——这个偏离就是匹配度进化的信号。

### 7.4 注入 prompt 的边界约定

提示词必须写清三件事，缺一不可：

```
本页需要 2 个装饰元素，可选用以下 6 个：
  · leaf      叶片（有机/簇状/轻）
  · leaf-2    叶片2（有机/单支/轻）
  · flower    花（有机/簇状/鲜艳）
  · seedling  幼苗（有机/单个/轻）
  · tree      树（有机/单个/中）
  · plant     植物（有机/单个/轻）

要求：
  1. 从中选用 2 个，并给出参数（count / scale / opacity）
  2. 不得选用上述列表以外的素材
  3. 不得自行生成新素材
```

三条边界：**可选项清单**（范围）、**需要量**（个数）、**禁止自造**（底线）。

## 八、引用契约（不变）

Skill 只拿 ID 与参数，永远不碰素材本体：

```json
{ "asset_id": "leaf-sprig", "tone": "accent", "params": { "count": 2, "scale": 1.2 } }
{ "asset_id": "number-line", "params": { "min": -3, "max": 3 } }
```

- `tone` 只能是语义槽（主色/强调色/弱化色），**不得出现色值**
- svg-mono 由 styleDNA 着色；位图忽略 tone，靠色系匹配度筛选
