# 课件模板外移方案（Backend 化管理）

> 提出背景：2026-08-28 会话中用户确认"模板仅在前端，是否应存数据库"。
> 结论：**应外移**，但目的不是让 AI 打标（模板自身已带完整标签），而是让模板可被后端
> 统一管理与按 facet 查询，支撑"生成课件时后端推荐模板"等能力。

---

## 一、PPT 模板与 H5 模板是否一致？

**结论：结构、风格标签体系、配色池完全一致，仅数据倾斜不同。可以统一一张表存储。**

代码事实（`frontend/src/lib/cwTemplate.ts`）：

| 维度 | PPT | H5 | 一致性 |
|------|-----|-----|--------|
| 类型 | `CwTemplate[]`（`PPT_TEMPLATES`） | `CwTemplate[]`（`H5_TEMPLATES`） | ✅ 同一接口 |
| 构建工厂 | `buildTemplates('ppt', PPT_TEMPLATE_DEFS)` | `buildTemplates('h5', H5_TEMPLATE_DEFS)` | ✅ 同一 `pptTemplate` 工厂 |
| 字段 | `id/kind/name/style/tags/colorFamily/themeId/layouts/globalDecor/demoOutline/subjects/grades` | 同 | ✅ 完全一致 |
| 风格标签 | `TplTag`：`style/stage/subject/scenario/pageType` | 同体系 | ✅ 共用 `STYLE_LABELS` |
| 配色 | `themeId` 引用 `pptThemes.ts` 的 `CwTheme` | 同 | ✅ 共用同一 theme 池 |
| 内置装饰 | `decorForStyle(style)` 按风格取 SVG | 同 | ✅ 与媒介无关 |
| 规模/倾斜 | ~56 套，风格均衡 | ~20 套，偏亮色/卡通（投屏平板更出彩） | ⚠️ 仅数据倾斜，规则一致 |

H5 模板源码注释明确写道：
> "与 PPT 共用同一套风格标签与配色，仅标签倾斜；规则体系完全一致（借鉴 51miz 互动场景）。"

**因此外移时，PPT 与 H5 用同一张 `courseware_templates` 表，靠 `kind` 字段区分即可，无需两套表。**

---

## 二、外移目标

1. **模板元数据入库**：`kind / name / style / tags / colorFamily / themeId / subjects / grades / demoOutline` 落库。
2. **内置装饰跟随模板**：`globalDecor`（按 `style` 绑定）可由后端按 `STYLE_DECOR_MAP` 规则生成，或随模板存表。
   - 当前前端用内联 SVG（`dataURL`）占位，待真实装饰元件上传后替换为素材库 URL。
   - **建议**：后端只存"按 style 引用"的语义（`globalDecor` 由 `style` 派生，不重复存 SVG 二进制），和前端现有逻辑一致。
3. **后端按 facet 查询模板**：`GET /courseware-templates?kind=ppt&style=china&subject=math&grade=junior`，
   返回匹配模板列表，供生成课件时的"智能选模板"使用（替代前端硬编码 `PPT_TEMPLATES.filter`）。
4. **运营可维护**：增删改模板走后端 CRUD，前端不再硬编码 `PPT_TEMPLATE_DEFS`。

---

## 三、不在外移范围内（保持现状）

- **配色 `themeId` 的解析**：仍由前端 `pptThemes.ts` 的 `CwTheme` 库负责（后端不维护 theme 表，
  避免重复维护同一份配色数据）。后端模板只存 `themeId` 字符串引用。
- **AI 打标**：模板**不需要** AI 巡增打标——其 `style/tags/colorFamily` 是"先天自带"语义标签。
  AI 巡增（阶段一）只针对**装饰元件**（`decor_element`/`decor_component`），两者解耦。
- **版式骨架 `layouts`**：`EDU_LAYOUT_SKELETONS` 是通用结构，与模板解耦，仍由前端提供（或后续抽为共享常量）。

## 四、表结构草案（Postgres）

```sql
CREATE TABLE courseware_templates (
  id           VARCHAR(64) PRIMARY KEY,
  kind         VARCHAR(16) NOT NULL DEFAULT 'ppt',   -- ppt | h5
  name         VARCHAR(128) NOT NULL,
  style        VARCHAR(32) NOT NULL,                 -- 主风格（StyleTag）
  color_family VARCHAR(32),                          -- 后生成色系描述
  theme_id     VARCHAR(64) NOT NULL,                 -- 引用 pptThemes 的 CwTheme
  tags         JSONB NOT NULL DEFAULT '[]',          -- TplTag[] 多维标签
  subjects     JSONB NOT NULL DEFAULT '[]',          -- 适配学科
  grades       JSONB NOT NULL DEFAULT '[]',          -- 适配学段
  demo_outline JSONB,                                -- OutlineSlide[] 示例提纲
  is_builtin   BOOLEAN NOT NULL DEFAULT true,        -- 平台内置 vs 用户自定义
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_tpl_kind_style ON courseware_templates(kind, style);
```

> `globalDecor` 不落库：由 `style` 经 `STYLE_DECOR_MAP`（后端等价实现）派生，避免存 SVG 二进制。

## 五、迁移与落地步骤（建议顺序）

1. 后端：建 `courseware_templates` 表 + migration `0008`。
2. 后端：seed 脚本把 `PPT_TEMPLATE_DEFS` + `H5_TEMPLATE_DEFS` 导入库（一次性的"前端常量 → DB"搬迁）。
3. 后端：新增 repository + handler + 路由：
   - `GET /courseware-templates`（按 kind/style/subject/grade 过滤）
   - `POST/PUT/DELETE /courseware-templates`（运营 CRUD，需鉴权）
4. 前端：新增 `templateAPI`（`lib/api.ts`），套模板/智能选模板改为从后端拉取。
5. 前端：保留 `cwTemplate.ts` 作为"模板运行期装配"层（layouts/globalDecor 派生），但**数据来源**从
   `PPT_TEMPLATES` 常量切到 `templateAPI.list()`；保留常量作为离线兜底。
6. 验证：PPT 与 H5 各套用一次，确认视觉与现有一致（一致性回归）。

---

## 六、风险与注意

- **一致性回归**：外移后须回归验证 PPT/H5 套用效果与原前端常量完全一致（尤其 `themeId` 解析、内置装饰）。
- **theme 解耦**：后端不存 theme，若前端 `pptThemes.ts` 调整 theme，模板 `themeId` 引用须同步——靠约束/文档保障。
- **真实装饰替换**：当前 `globalDecor` 是占位 SVG，待素材库装饰元件就绪后，需在后端/前端统一替换为素材库 URL。
