# H5 场景版式扩展提案：自然科学互动组件 + 家校/宣发类 H5

> 日期：2026-09-03 ｜ 状态：**提案待评审**（先评审方向，再分阶段实现）
> 背景：H5 场景版式 v1（7 类）已落地。本提案回答两个问题：
> ① v2 加哪些「自然科学互动组件」（天气/雷电等，有互动优先）；
> ② 新增「家校/学校宣发类 H5」——它不是课件，是全校共享的宣发资产。

---

## 一、自然科学互动组件（H5 组件层 v2）

### 1.1 设计原则

- 组件 = 一个可交互的「现象小块」，挂在某个场景内，与现有 read/quiz/reveal/draw 平级。
- 科学课特点：**现象→原理→验证**。组件服务「现象演示/模拟验证」，避免纯文字灌输。
- 全部用 Canvas/CSS/WebAudio 实现，不依赖外部素材；音效优先用 WebAudio 合成（雷声=低频噪声包络、雨声=白噪滤波、鸟鸣暂缓），零版权风险。
- 组件一律「先点击再出现」，符合课堂节奏（不是自动动画播完）。

### 1.2 组件清单（7 个候选，按实现成本从低到高）

| 组件 | 语法 | 触发 | 视觉/音效 | 适用内容示例 |
|---|---|---|---|---|
| `weather` 天气切换 | `<!-- weather: 晴,多云,阴,雷阵雨 -->` | 点按钮循环切换 | 背景天空/云/太阳/雨滴粒子随选项变化；雨有雨声 | 三年级《天气》、英语 weather 主题 |
| `storm` 雷电模拟 | `<!-- storm: 雷电是怎么形成的？-->` | 点云朵 → 放电 | 云内电荷 + 雷声（低频轰鸣）+ 闪电画线闪过 | 四上《声音》？实为《天气》拓展/科普 |
| `rain` 粒子雨雪 | `<!-- rain: 慢|快 -->` | 自动 + 点调速度 | 雨/雪粒子密度可调，可切雨/雪/雹 | 观察自然、写景课文配景 |
| `cycle` 现象循环 | `<!-- cycle: 水循环:蒸发=>凝结=>降水=>径流 -->` | 点「下一步」推进 | 步骤条 + 每步图示(emoji)与一句说明 | 水循环/四季/月相/昼夜/植物生长 |
| `sound` 自然之声 | `<!-- sound: 雷声,雨声,风声,溪水 -->` | 点击试听 | WebAudio 合成音效 | 低年级聆听自然、语文拟声 |
| `observe` 放大镜 | `<!-- observe: 石头上的花纹 -->` | 拖镜观察 | 圆形镜头放大底图 | 科学观察（岩石/昆虫/树叶） |
| `compare` 现象对比 | `<!-- compare: 白天 vs 黑夜 | 有光 vs 无光 -->` | 左右拨杆切换 | 半屏切换两种状态 | 昼夜成因、影子的产生 |

**v2 与 v1 场景的关系**：组件挂在场景内（`scene-dialog`/`scene-read` 等都可携带）；
同时把「以现象演示为主的一页」单列为 v2 场景版式 `scene-phenomenon`（现象页：大组件占主体，
旁白精简、无对话），让科学课件能整页聚焦一个现象。

### 1.3 实现要点

- 新增组件解析进 `mdToStory.applyInteraction`（`weather/storm/rain/cycle/sound/observe/compare`）。
- 渲染：`interaction.type` 新增对应分支；效果脚本并入 RUNTIME_JS；音效用 WebAudio 合成器。
- Skill：`courseware-h5/references/` 增《自然科学组件规范》，约束组件与内容匹配（不许把 `storm` 用在非气象主题）。

## 二、家校/学校宣发类 H5（新分类，非课件）

### 2.1 定位与数据归属（关键差异）

| 维度 | 现状课件 | 宣发 H5（新增） |
|---|---|---|
| 属性 | `type=courseware, format=h5` | `type=notice, format=h5, category=notice`（新 category） |
| 性质 | 教学课件 | **宣发/通知页**（防溺水、开学季等） |
| 归属 | school 内全体教师可见 | **全校共用资产**（school 级共享，不属某位教师） |
| 更新 | 教师备课发布 | 校方/年级/班主任制作后发布，可置顶、可设有效期 |
| 分享 | 投屏/扫码进课堂 | 公众号转载 + 家长扫码 + 家校群转发；**可设已读/回执** |

复用现有 H5 渲染底座（场景滚动/翻页），但内容模板与红线段位不同（见 2.3）。

### 2.2 场景清单（学校公众号高频主题调研整理）

**A. 安全警示类（季节性强、多为教育局要求推送）**
1. 防溺水（六不一会 + 家长监护提示 + 落水自救）
2. 交通安全（开学/放假节点）
3. 消防安全 · 防震减灾
4. 防欺凌 · 防性侵 · 网络安全（反诈）
5. 食品/传染病安全（流感、诺如、手足口）

**B. 节点通知类**
6. 开学啦 / 新学期寄语（含备物清单、作息调整）
7. 放假通知（寒暑假/节假日 + 作业单 + 安全提醒）
8. 报到注册指引（时间/地点/携带材料/分班查询）
9. 家长会邀请函（时间地点议程 + 回执）
10. 考试安排 / 报名通知

**C. 健康卫生类**
11. 近视防控（爱眼日）
12. 疫苗接种（流感疫苗/查验补种）
13. 心理健康（讲座邀请 + 求助热线）

**D. 家校共育类**
14. 致家长的一封信（假期信/防溺水信/诚信考试倡议）
15. 家庭教育讲座 · 亲子阅读/劳动倡议

**E. 展示宣传类**
16. 招生简章（学校介绍/特色/报名流程）
17. 喜报/获奖/校园新闻
18. 活动回顾（运动会、文艺汇演、研学）——图册型
19. 开学第一课（安全教育 + 收心）

**模板化思路（一页一模块）**：封面(标题+校名+日期) → 要点正文（卡片） →
互动确认（防溺水"六不"勾选/签收）→ 结束页(家长留言/回执)。不同场景替换内容骨架即可。

### 2.3 特殊约束（与课件不同）

- **红线口径**：安全类内容须对齐官方口径（如防溺水"六不一会"、交通"一盔一带"），
  不允许 AI 自行演绎安全条款 —— 需要独立的 notice 提示词模板 + 内容白名单。
- **签名/回执**：可挂「家长已读回执」，需后端记录（家长侧已有签到体系可复用）。
- **置顶与有效期**：notice 支持置顶、过期自动下线。

### 2.4 入口与创建流程（建议，待定）

- 建议入口：家校沟通频道（与家长会/通知同类）或课程频道旁的「宣发」页签。
- 建议流程：选场景模板 → 填内容（AI 补全但受红线段位约束）→ 预览（扫码看手机效果）→ 发布全校。

## 三、待评审决策点

1. **v2 组件**：上表 7 个是否全做？建议先做 `weather` + `storm` + `cycle`（成本低、课堂价值高）。
2. **宣发归属**：按 2.1 表加 `type=notice`（新字段语义），还是复用 materials 另加 category？建议前者。
3. **谁能创建**：校务/德育岗 vs 全体教师？建议：德育/校务 + 班主任（需角色或申请），且过**宣发专用红线**。
4. **回执/置顶**是否本期做（涉及家长侧与后端记录，工作量中等）。

## 四、实施顺序建议（评审后）

1. 组件 v2：Skill 规范 → 解析/渲染 → 单测 → E2E → 与课件重跑联动（先 3 个组件）
2. 宣发 H5：模板库（先 5 个高频场景：防溺水/开学啦/放假通知/家长会邀请/招生）→
   notice 数据模型 → 编辑/发布 → 家长扫码查看
