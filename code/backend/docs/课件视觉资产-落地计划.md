# 课件视觉资产 - 落地计划

> 配套文档：`课件视觉资产架构方案.md`
> 原则：**先定契约，再试点验证，最后铺开**。每阶段可独立验证，不依赖后续阶段。

---

## 阶段总览

| 阶段 | 内容 | 产出 | 依赖 | 估时 |
|---|---|---|---|---|
| **S1** | 四份核心 schema | TypeScript 类型 + JSON Schema | 无 | 1d |
| **S2** | baseline 验证 | 差距清单（量化自建价值） | 无（可并行） | 0.5d |
| **S3** | 装饰资产库试点（H5） | forest 风格资产 + 渲染打通 | S1 | 2-3d |
| **S4** | 小微闭环 | 焦点感知 + 指令结构化 + 反馈池 | S1, S3 | 2-3d |
| **S5** | PPT 视觉质量攻坚 | 解决字密/撑破 + 打破框线 | S1 | 3-4d |
| **S6** | 校准引擎 | 默认参数进化 + 命中率度量 | S4 | 2-3d |
| **S7** | 结构层与 H5 扩展 | Skills 自选结构 + H5 支持 visual | S1, S5 | 4-5d |

**并行建议**：S2 不阻塞任何阶段，可与 S1 同时推进。

---

## S1 · 四份核心 schema（地基）

**目标**：定下所有后续工作的契约。不定好会返工，所以必须最先做。

**任务**
1. 新建 `frontend/src/lib/visualAsset/types.ts`：
   - `StyleDNA` —— 风格快照（配色/字体/密度/装饰语汇）
   - `DecorAsset` + `AssetParam` —— 装饰资产（视觉特征/风格归属/位置/可调参数/按风格默认值）
   - `StructureSpec` —— 结构决策（layout/visualType/derivedFrom/locked）
   - `AssetFeedback` —— 校准信号（资产/风格/参数/操作/类型/置信度）
2. 导出 JSON Schema，供 ai-service（Python）提示词约束输出格式
3. 向后兼容：所有字段可选，缺省回退现有行为

**验证标准**
- `tsc` 通过
- 现有课件渲染无回归（老数据无新字段，走默认分支）

---

## S2 · baseline 验证（可并行）

**目标**：用现成能力生成一个版本，跟手搓黄金样本对比，量化"自建到底值多少"。

**任务**
1. 用现成 pptx 能力，以《观潮》教案为输入生成一份课件
2. 与黄金样本逐页对比，按维度打分：
   - 课标对齐、教学节奏（导入-探究-练习-小结）、互动环节
   - 学科专用组件（田字格/数轴）、年龄适配、视觉密度
3. 产出差距清单

**验证标准**：明确列出"现成能力覆盖"与"必须自建"的边界。

---

## S3 · 装饰资产库试点（H5）

**目标**：在渲染能力最强、无导出包袱的一端，先把装饰层的天花板探出来。

**为什么先在 H5**：PPT 受 pptxgenjs 限制（仅 rect/ellipse/line/triangle），H5 是完整 CSS。先在 H5 验证哪些装饰维度有效，再把验证过的下沉到 PPT，避免 PPT 端大面积降级。

**任务**
1. 以 H5 现有 `forest` 皮肤为试点，按 `DecorAsset` 描述其装饰资产
2. 建立资产库数据结构 + 查询接口（按风格/位置/视觉特征检索）
3. H5 渲染器支持装饰参数（count / scale / opacity / placement）
4. 装饰配色绑定 `StyleDNA`，换风格自动换色

**验证标准**：同一份内容，接入装饰资产前后视觉效果对比；换风格时装饰自动跟随。

---

## S4 · 小微闭环

**目标**：让"用户修改指令"能转化为结构化校准信号。

**任务**
1. 结构化焦点：替换现有 `xiaoweiContext`（当前仅 6 条纯文本 + sessionStorage）
   - 加入 `focus`：materialId / slideIndex / assetId / assetParams / versionId
2. 修改指令 → 结构化变更：自然语言映射到 `{asset, param, op}`
3. 反馈分类：区分 `defect`（通病）/ `preference`（偏好）/ `content`（个案）
4. 建 `asset_feedback` 反馈池（先记不算）
5. 隐私护栏：反馈表禁自由文本；个人偏好写入隔离的 `user_style_profile`

**验证标准**：小微能接收"云朵太多了" → 当场调整 + 落一条结构化反馈；偏好类不污染全局。

---

## S5 · PPT 视觉质量攻坚

**目标**：直接解决用户截图暴露的痛点（字密、表格撑破、框线版块）。

**任务**
1. **打破框线**：把渲染层硬编码的 `border/background` 换成按 deco 参数计算
2. **解字密**：
   - 学习目标页（edu-goal）禁用 card 类组件，只走 bullets
   - 收紧 card 类字数上限；单项超阈强制分流到 annotate/compare-table
3. **解撑破**：
   - compare-table 列名语义校验（禁"关系1/关系2"这类无意义编号）
   - 行数上限收紧；列数超限时自动减列
4. 重跑《函数》，截图对比

**验证标准**：P1 学习目标页变成清爽大字；P4 判断页结构完整不截断；用户认可。

---

## S6 · 校准引擎

**目标**：让反馈池真正驱动默认参数进化。

**任务**
1. 聚合逻辑：按 `asset_id × style_id × param` 分组，累计 op 分布
2. 阈值与迟滞：同类反馈 ≥ N 次才调整；收紧易、放宽难（防震荡）
3. 最小样本量：分组样本 < 20 不输出（k-anonymity）
4. 分级生效：`capacity`/`count` 类可自动；`semantic` 类需人工确认
5. 命中率度量与看板

**验证标准**：模拟一批反馈，默认值按预期收敛；单人反馈不触发全局变更。

---

## S7 · 结构层与 H5 扩展

**目标**：结构交给 Skills 自选，并让 H5 能承载知识结构类内容。

**任务**
1. 结构跟随纲要：把现有映射规则（generate_seed_coursewares.py）提升为 Skills 先验
2. 三道安全网：受控原语 + 容量校验 + 降级到 bullets
3. 结构快照与 `locked` 标志（保护教师手动调整）
4. H5 渲染器支持 visual block（先 icon-card / compare-table / annotate 三种）
5. 纲要特征 → 结构 的命中率统计

**验证标准**：Skills 自选结构可用；教师改过的结构不被重算冲掉；H5 能渲染知识结构。

---

## 执行纪律

1. **每阶段结束必须验证**，验证不过不进下一阶段
2. **schema 变更走版本**，不做破坏性修改
3. **优先解决可见的质量问题**，架构建设服务于体验改善，不为架构而架构
