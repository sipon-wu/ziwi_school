# 课件视觉资产架构方案

> 定位：**课件视觉生产**的领域知识与数据契约
> 起因：固定模板装不下自由内容，导致"字密""表格撑破""千篇一律的框线版块"
> 核心判断：**形式服从内容** —— 模板提供风格与资产，结构交给 Skills，装饰参数由用户反馈持续校准
> 状态：方案已定，进入分阶段落地

---

## 一、问题起源

《函数》课件暴露的三个症状：

| 症状 | 表象 | 实质 |
|---|---|---|
| 字密到不可读 | 学习目标页塞进 3 个卡片，字号被压到极小 | 容器驱动：先有框，再往框里塞内容 |
| 表格撑破截断 | compare-table 列名无语义（"关系1/关系2"），行数超限 | 模板固定槽位，内容超量即崩 |
| 千篇一律的框线 | 11 类组件渲染出来都是圆角方框 | 外观硬编码在渲染层，与内容无关 |

**根因**：`模板 = 带槽位的结构容器`，内容被迫削足适履。前面所有修复（字数契约、形态匹配、clamp 截断、自适应字号、降级放行）都是在缓解这个矛盾，而非解决。

---

## 二、核心理念

### 1. 形式服从内容

```
传统（模板驱动）：模板（固定结构）+ 内容 → 填充输出
本方案（风格驱动）：内容 + 风格语汇 → Skills 现场设计版式 → 输出
```

模板从"内容的模具"变成"审美的共识"。分工逻辑：**AI 擅长生成结构，人类擅长定义审美**。

### 2. 模板即风格示意

模板的价值是**可复用性**：快速启动 + 省 token。它提供两样东西：

- 一套风格语汇（配色 / 字体 / 气质 / 禁忌）
- 一批可引用的装饰资产

它**不提供**结构——结构由 Skills 跟随内容纲要自行选择。

### 3. 分层不可变性

不是"全部快照"或"全部引用"，而是按层划定不可变性边界：

| 层 | 策略 | 理由 |
|---|---|---|
| 风格 DNA | ✅ 快照进课件 | 老课件外观必须稳定 |
| 结构决策 | ✅ 快照进课件 | 教师手动调过的结构不能被重算冲掉 |
| 装饰参数 | ✅ 快照进课件 | 同上 |
| 渲染器代码 | 🔄 可演进 | 渲染改进是纯增益，老课件自动变好看 |
| 风格描述卡 | 🔄 可演进 | 放服务端持续优化，只影响新生成 |
| template_id | 📌 仅追溯 | 不参与渲染，改模板不影响老课件 |

**致命陷阱**：若课件只存 `template_id` 实时读模板，模板改一次配色，所有历史课件外观全变——不可接受。

## 三、四层模型

| 层 | 谁决定 | 快照 | 进化信号 | 校准什么 |
|---|---|---|---|---|
| **① 风格** | 人类选模板 | `style.dna` | 模板迭代（人工） | 人工发布新版本 |
| **② 结构** | Skills 跟随纲要自选 | 每页 layout + 结构 | 用户对结构的调整 | 纲要特征 → 结构 的映射 |
| **③ 装饰** | Skills 引用资产库 | 每页 deco 参数 | **用户修改指令** | 资产 × 风格 的默认参数 |
| **④ 渲染** | 确定性代码 | 不快照 | 渲染技术升级 | 无（纯增益） |

三层的进化机制同构：**先验 → 使用 → 后验 → 回流入库**，区别只在信号来源与校准对象。

## 四、数据结构

### 4.1 StyleDNA（风格快照，进课件）

```ts
interface StyleDNA {
  templateId: string        // 仅追溯
  templateVersion: number   // 仅追溯
  colors: { primary: string; accent: string; body: string; subtle: string }
  font: { title: string; body: string }
  density: 'compact' | 'normal' | 'spacious'
  decorVocab: string[]      // 该风格允许的装饰母题
}
```

几十字节，渲染时只依赖它，**不读 template_id**。

### 4.2 DecorAsset（装饰性资产）

装饰资产与结构元件的根本区别：**不承载内容、无强语义约束**，描述重点是视觉特征与可调参数。

```ts
interface DecorAsset {
  id: string                       // 'leaf-cluster'
  visual: {
    form:    'organic' | 'geometric' | 'linear' | 'texture'
    density: 'single' | 'cluster' | 'scattered' | 'tiled'
    weight:  'light' | 'medium' | 'heavy'
    tone:    'muted' | 'vivid' | 'mono'
  }
  styleAffinity: string[]          // 归属哪些风格
  placement: Placement[]           // corner | edge | background | divider
  params: Record<string, AssetParam>

  /** 按风格分化的默认值 —— 命中率的战场 */
  defaultsByStyle?: Record<string, Record<string, number | string>>
}

interface AssetParam {
  default: number | string
  range?: [number, number]
  enum?: string[]
}
```

关键点：`defaultsByStyle` —— 同一片树叶在「森林童趣」里默认 2 朵，在「自然生机」里默认 8 朵。**校准的键是 `asset_id × style_id`，不是 asset_id**。

### 4.3 StructureSpec（结构决策，进课件）

```ts
interface StructureSpec {
  layout: string            // edu-goal | content-2col | ...
  visualType?: string       // compare-table | icon-card | ...
  derivedFrom: string       // 推导依据（纲要特征），用于后续进化归因
  locked: boolean           // true = 教师手动调过，禁止 AI 重算
}
```

`locked` 是保护教师劳动的关键：教师把 3 列改成 2 列后，重新打开不能被重算冲掉。

### 4.4 AssetFeedback（校准池）

```ts
interface AssetFeedback {
  assetId: string
  styleId: string
  param: string             // 'count' | 'scale' | ...
  op: 'increase' | 'decrease' | 'set' | 'disable'
  value?: number | string
  feedbackType: 'defect' | 'preference' | 'content'   // 通病 / 偏好 / 个案
  confidence: number
}
```

只有 `defect`（通病）参与全局校准；`preference` 只写个人画像；`content` 不入池。

## 五、双端渲染与能力分级

| Tier | 能力 | PPT（pptxgenjs） | H5（完整 CSS/SVG） |
|---|---|---|---|
| **0** | 基础形状（框/线/圆/三角） | ✅ 原生 | ✅ |
| **1** | CSS 效果（blob/波纹/渐变/点阵） | ⬇️ 降级为 Tier0 近似 | ✅ 完整 |
| **2** | 动画 / 交互 | ❌ 静态 | ✅ |

约束来源：PPT 导出用的是「原生形状 + 表格」，以保证教师可编辑：

```
code/frontend/src/lib/exportPptx.ts
* 把可视化组件绘制到 PPTX（形状 + 原生表格），与预览端 VisualBlocks 视觉一致。
* 用 pptxgenjs 的 shape/table，保证导出的是可编辑的原生对象而非图片。
```

因此 **AI 只决定"长什么样"，不产出"画出来是什么"** —— 渲染必须回到结构化对象，否则教师无法编辑。

## 六、闭环机制

### 6.1 双通道：一次反馈，两个产出

```
        用户向小微反馈"云朵太多了"
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
【通道 A · 同步 · 面向当下】  【通道 B · 异步 · 面向全局】
 改的是「这一份课件」          改的是「资产默认参数」
 小微 → 调参 → 重渲染         小微 → 归因 → 入反馈池
 ⚡ 秒级，用户当场满意          ↓ 同类累积达阈值
                             修正 asset×style 的 default
                             ⏳ 天级，所有人受益
```

**通道 A 绝不触发通道 B 的即时修正** —— 一个人的一次抱怨不能直接改全局默认值。

### 6.2 目标指标：引用命中率

```
命中率 = 1 - (用户修改过的装饰资产数 / 引用的装饰资产总数)
```

按 `风格 × 资产` 分组统计，低命中组合即优先校准对象。

### 6.3 必须区分的三类反馈

| 类型 | 例子 | 判据 | 处理 |
|---|---|---|---|
| **个案** | "这个例子不合适" | 指向内容，非资产通用属性 | 只改当前，不入池 |
| **通病** | "刻度太密" | 指向资产通用属性 + 多人复现 | 入池，累积校准 |
| **偏好** | "我不喜欢圆角" | 个人审美 | 写个人画像，**绝不改全局** |

**偏好误判成通病是最大污染** —— 一个教师不喜欢圆角，不该让全校课件变直角。

### 6.4 信号强度排序

| 信号 | 强度 | 说明 |
|---|---|---|
| 多候选中选了一个 | ⭐⭐⭐⭐⭐ | 对比式偏好，无歧义 |
| 主动删除某资产 | ⭐⭐⭐⭐ | 明确否定 |
| 主动调整参数 | ⭐⭐⭐ | 方向明确 |
| 重新生成 | ⭐⭐ | 不满，但不知不满在哪 |
| 默默接受 | ⭐ | 弱正信号 |

**设计推论**：小微在关键决策点应主动提供 2~3 个候选。既给教师控制权，又顺带采集最强信号——**把采集嵌进用户本来就要做的选择里**，而非额外要求反馈。

## 七、数据主权边界

```
┌─ 私有层（用户拥有）
│   个人风格画像、历史产出、私有素材
│   平台：仅提供存储与计算，可导出、可清除
│
├─ 公共层（平台拥有）
│   资产定义、使用场景统计、适配度
│   来源：匿名聚合，无 user_id，无自由文本
│
└─ 单向流动
    上行：仅结构化的匿名行为统计（不含内容）
    下行：平台改进的资产能力赋能所有用户
```

### 两条硬护栏

1. **最小样本量（k-anonymity）**：任何统计分组样本数 < 20 不输出、不入表
   —— 防止"某校唯一的八年级数学教师"被反推定位
2. **禁自由文本**：写入统计表的字段必须是枚举/数值，**schema 层面堵死**
   —— 可上平台：「刻度 8→5」这类结构差异
   —— 不可上平台：教师写的具体例句、在小微里说的话

### 工程落点：两张表物理隔离

```sql
-- 私有：按 user_id 强隔离，不参与平台统计
user_style_profile (user_id, profile JSONB)

-- 公共：无 user_id、无自由文本字段
asset_usage_stat (asset_id, context_dim, action, param_key, direction, count)
```

## 八、小微的角色

小微是统一入口（见 `课件生成Skills架构方案.md`），在闭环中承担感知与执行。

### 8.1 分层记忆

当前实现只有最近 6 条纯文本存 sessionStorage，这是随手写的截断，非技术瓶颈。

```ts
interface XiaoWeiMemory {
  focus: {                  // 当前焦点（最高优先级，永远带）
    materialId: string
    slideIndex: number
    assetId?: string
    assetParams?: unknown
    versionId?: string
  }
  profile: object           // 长期画像：结构化，几 KB 覆盖全部历史偏好
  recent: Message[]         // 近期原文：滑动窗口，保真
  summary?: string          // 历史摘要：超出窗口的压缩
  recall?: EmbeddedChunk[]  // 检索池：向量化，按需取回
}
```

**按 token 预算组装，不按条数截断**（预算 2000，优先级从高到低装入，装不下砍低优先级）。

### 8.2 修改指令 → 结构化变更

| 用户指令 | 结构化 |
|---|---|
| "云朵太多了" | `{asset:cloud, param:count, op:decrease}` |
| "树叶换小一点" | `{asset:leaf, param:scale, op:decrease}` |
| "点线再细些" | `{asset:dotline, param:weight, op:decrease}` |
| "不要叶子了" | `{asset:leaf, op:disable}` |

## 九、与 Skills 架构的关系

### 底层用现成，上层自建

```
┌─────────────────────────────────────────┐
│  自研 courseware.generate Skill          │  ← 必须自建
│   · sop: S0-S5（课标守门 → 交付入库）     │
│   · 领域知识：宪法 / 选型规则 / 质检标准   │
│   · tool: template.query → 风格库         │
│   · tool: asset.search   → 资产库         │
│   · tool: visual.check   → 质检           │
│   · tool: slide.render   ↓               │
└──────────────────┬──────────────────────┘
                   ↓ 调用底层
┌─────────────────────────────────────────┐
│  现成能力（直接用，别造）                 │
│   pptx 官方 skill / pptxgenjs / H5 渲染器 │
└─────────────────────────────────────────┘
```

**现成 Skill 解决「怎么生成 PPT 文件」，不解决「怎么生成一节好课」。** 后者是护城河，且团队已有积累（56 套主题、选型规则、质检设计、审核留痕），只是散落在代码与对话中。

### 结构跟随纲要

结构是内容的投影，纲要确定后可选范围很窄。团队已摸出映射规律（见 `generate_seed_coursewares.py`）：

- 层层推进 / 有先后顺序 → sequence / flow / timeline
- 二维对照 → compare-table
- 两项辨析 → compare-card
- 知识层级 → structure
- 并列多方面 → diagram / icon-card

让 Skills 自选 = **以这套规则为先验，泛化到规则未覆盖的情况**，而非从零发挥。

**三道安全网**：受控原语（不能发明新类型）+ 容量校验（3 条内容不能塞 2 槽位）+ 可降级（失败退回 bullets 平铺）。
