## 1. 编辑器（同框架，异 I/O）

概念上六产出，本期落地**四件套**（教案 / 出题含题单 / 组卷 / PPT），H5 仅插槽、题单并入出题为内部视图。

| 产品 | 模板区 | 编辑态右栏 | 预览 | 导出 | 保存 |
|---|---|---|---|---|---|
| 教案 | 教案模板（核心素养/三维目标/单元教学/更多） | A4竖向单列，所见即所得 | A4竖向·全屏·不可编辑 | 版式A4 / word·pdf | 内容+版式 |

## 2. 每个产品的统一三层结构（来自 xmind「调共用框架」）

```
调共用框架
├─ 编辑
│  ├─ AI编辑模式   左=信息栏  右=知识图谱画布视图
│  └─ 文档编辑模式 左=信息栏  右=主编辑器（产品特定）
├─ 预览  → 同全屏预览承载层（不可编辑；内里按产品语义：文字类=锁定只读版式 / PPT=放映态 / H5=运行态，可选步骤）
└─ 保存  → 内容±版式（自动保存 / 草稿 / 发布）
```

**信息栏（左）在 AI模式 与 文档模式 下字段完全一致**，仅右侧不同：
- 基本信息：学科 / 班级 / 校区 / 教材版本及封面
- 标题（AI自动生成，可编辑）
- 单元-课时（下拉，按记忆进度自动匹配，可重选）
- 模板区（产品特定：教案模板 / 无 / 试卷版式 / PPT风格 / H5模板）
- 知识点（已选，默认核心知识点与课标对应，可×掉由右侧点选）
- 附加关键字、标签
- 小微工具会话式补充输入
- 保存区：自动保存（无感） / 存草稿 / 预览(可选) / 发布

> 注：预览是**可选校验步骤**，非发布必经（参照微信公众号图文流，但我们预览为全屏预览承载层、非发手机端）。

## 3. 框架职责边界（核心）

### 框架（EditorLayout）拥有 —— 所有产品共用，只写一次
1. 整体布局：顶栏 + 左信息栏 + 右主区 + 底栏（footer）。
2. 左信息栏容器 + 通用字段渲染（P0-3 拍板：丙·通用渲染+slot注入 + A·全局字段走 TeachingContext）：框架 `InfoPanel` 默认渲染通用字段——学科/年级/班级/校区/教材版本/标题/单元课时/知识点/标签/小微输入/保存区。**字段值归属**：学科/年级/班级/教材版本 走 `TeachingContext`（全局教学上下文，根治 TC-SYNC 同步隐患，呼应 memory 81529730）；标题/单元课时/标签/关联课件 走编辑器局部 state。**差异注入**：产品通过 `productTemplateSlot`（固定插在「标题」下，承载 教案模板/试卷版式/PPT风格/H5模板）、`productExtraSlot`（固定插在「标签」下，承载 关联课件/题单间隔 等）注入产品特定片段；隐藏某通用字段用 `hiddenFields`。小微展开+景版(opacity)由 InfoPanel 内置，随 P0-4 一并处理。**前置**：确认/补齐 `TeachingContext` 覆盖 班级/校区/教材版本（现状疑似仅 subject/grade，见 `LessonPlanEditor:86` 本地镜像；补齐属多校区前提 A1，本就该做）。
3. **AI模式 ↔ 文档模式** 切换机制（同一套左栏，切右栏）。**内容态桥接（P0-5 拍板：页面级 content + 框架管 `useEditorBridge` 交互桥接）**：`content` 状态**留在页面级**（四产品内容结构差异大——富文本/题单流/结构化 `selectedQuestions`/幻灯片 markdown，框架强行统一 `useEditorContent` 属过度设计，且与 P0-3"产品特定不进框架"原则一致）；框架只提供 `useEditorBridge()` 管"AI生成→文档态"的**交互桥接**——内部 `{ generating, error, runGenerate(aiFn) }`，`runGenerate` 调页面传入的 AI 函数、管 loading/报错、成功后交页面 `commitToDoc(result)` 写自身 content + 切到 doc 模式 + 标记"预后可编辑"。各页 `handleGenerate` 从"自管 loading+setContent+切模式"简化为"传 AI 函数给 `runGenerate`"，消除重复且统一体验。
4. **预览按钮**：框架统一触发**全屏预览承载层（不可编辑）**——四件套共用"外壳"（全屏+不可编辑+一键返回+标题栏）；外壳内渲染由产品通过 `previewSlot` 注入，因产品而异：文字类=锁定只读版式，PPT=放映态（播放器），H5=运行态 iframe。PPT/H5 预览是进入播放/运行态而非"锁定编辑"，但均不可编辑、走同一外壳。（P0-2 选 B：框架统一接管预览，不保留"切文档模式"老行为。）
5. **保存动作（P0-6 拍板：抽 `useEditorLifecycle` + footer 框架统一渲染 + C·混合自动保存 + A·仅前端状态机）**：框架统一 footer（自动保存/草稿/发布），业务只传 `saveDraftLabel/publishLabel` + 回调 `onSaveDraft/onPublish`，文案与落库各页自理（根治铁律禁止的"各页自画底栏"，见 `LessonPlanEditor:777/ExerciseGenerator:822`）。`useEditorLifecycle()` 只管**交互与状态机**（`status: unsaved→autosaving→draft→published` + `dirty` + `lastSavedAt` + `saveDraft()/publish()/touch()`），落库仍走各页现有 api（lessonPlanAPI/questionBankAPI 等），**不新增后端字段、不碰后端**（点2=A：草稿态是前端 UI 态，真正落库由各页 `onSaveDraft` 调 api 完成，后端 draft 概念已存在如 `editQuestion.status`）。**自动保存策略=混合 C**：内容停手 N 秒（如 8s）debounce 才存（省请求、不频繁打扰）+ 切文档/失焦/离开页面时强制 flush；统一各页体验（现状 `LessonPlanEditor:167` 是 30s interval 且 `ExerciseGenerator` 无自动保存，四页不一致）。
6. 模板选择器的「容器与位置」（选项内容由产品传入）。
7. **右侧批注 / 版本面板（框架通用件，A6 新决策）**：各产品的批注与版本历史**统一置于右栏浮层/面板**（与 Word 编辑器一致），由各产品注入内容；**禁止各产品自画顶栏菜单放版本**（违反铁律）。

### 产品（page）拥有 —— 通过 props/slots 注入框架
1. 信息栏「模板区」内容（教案模板 / 试卷版式 / PPT风格 / H5模板 / 无）。
2. 右侧主编辑器组件（A4富文本 / 组卷多栏 / PPT画布 / H5轻量编辑器）。
3. 预览 render（按产品版式：A4 / 组卷四版式 / PPT按比例 / H5按比例+扫码）。
4. 导出选项配置（版式枚举 + 格式）。
5. 保存 payload 构造（带不带版式）。
6. 右侧批注/版本面板的内容注入（框架提供容器与统一样式）。

> 铁律：**交互骨架一次写对，四件套只填 I/O**。任何「预览/模式切换/保存/信息栏/批注版本面板」的改动都只在框架层，禁止每个页面各画一遍底栏或顶栏（前车之鉴：教案崩溃即因各页自绘底栏 + 误用 useBlocker）。

### 6.1 排重算法建议（答 Q-B）
用户观察：出题一次生成多道时「题面绝大部分相同」。目标：避免把相同题重复入库，但保留合法变体（仅数字/专名不同）。

两级去重（先快后精，均按 **题型 + 知识点** 分区，避免跨类误并）：
1. **Tier1 归一化精确哈希（必做，O(1)）**
   - 题面 NFKC 归一化 → 去空白/标点/全角半角统一 → 小写；拼接 题型 + 知识点。
   - `key = SHA256(normalized_stem + type + knowledge)`。
   - 命中即同题，跳过入库（仅关联题单）。覆盖「完全同题」「仅标点/空格差异」。
2. **Tier2 MinHash + LSH 近重复（覆盖「题面绝大部分相同」）**
   - 对题面做字符 3-gram shingling → 构建 MinHash 签名（如 128 桶）→ LSH 分桶。
   - 同桶内算 Jaccard 相似度，阈值 **>0.92** 判近重复 → 跳过。
   - 数字/专名不同的合法变体：因 shingle 含数字，相似度会降到阈值下，自然保留。
3. **Tier3 语义（后续，接有据引擎）**：题面 embedding（百炼 text-embedding）→ PGvector 近邻，相似度 >0.95 判近义重复。本期不做，留接口。

> 说明：纯变体（只换数字）不是重复，Tier1/Tier2 均不会误杀；真正「题面绝大部分相同」的复制品被 Tier2 捕获。无需每次调用 LLM，成本低。

## 7. 已拍板 / 待确认细化（Q-E ~ Q-L）

## 9. 生命周期：自动保存 → 草稿 → 预览 → 发布
参照微信公众号图文流（预览为全屏预览承载层，非手机端）。四产品统一：
1. **自动保存（无感）**：实时防丢（本地 + 服务端增量），不显式进入草稿态，用户无感知。
2. **草稿（显式暂存）**：手动存草稿（未完成 / 需线下校对时暂存，如地方志类题型），进入服务端草稿态。前端 `status` 状态机：`unsaved→autosaving→draft→published`（`useEditorLifecycle` 管理，`dirty` 标记变更），草稿态为**前端 UI 态**，真正落库由各页 `onSaveDraft` 调现有 api 完成，不新增后端字段（P0-6 拍板 A）。
3. **预览（可选）**：框架全屏预览承载层，不可编辑、一键返回；**内里语义按产品**：文字类=锁定只读版式，PPT=放映态（播放器），H5=运行态（iframe）。返回即预后编辑。
4. **发布**：定稿后落对应库（教案库 / 题库+题单 / 试卷库 / 课件库），进入可用态。
