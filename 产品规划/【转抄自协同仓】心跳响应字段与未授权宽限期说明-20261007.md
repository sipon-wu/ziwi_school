# 心跳响应字段变更与「未授权宽限期」规则（2026-10-07）

> 契约真相源：`contracts/mfg接入cloud接口契约.md`（§D 心跳）。本文件是**面向接入方（mfg / school / 私有化实例）的实现说明**，随心跳服务端上线同步。

> 服务端版本：`ziwi_cloud@840e893` → `c94803c`（heartbeat 服务已部署上线，2026-10-07）

## 一、Q2 裁定内容（一句话）

**未授权（`none`）也视为需限制，但给 30 天容错期：期间功能全开、只做界面浮层提醒；超期才启用限制。**

| 心跳响应 `license_status` | 机器端应采取的行为 |
|---|---|
| `active` / `trial` | 全功能 |
| `none` 且 **当前时间 < `grace_until`** | **全功能 + 小窗浮层提醒**（文案含"未授权"与剩余天数/截止日） |
| `none` 且 **当前时间 ≥ `grace_until`** | 启用限制：**禁止新增/修改业务数据**（新建工单、改 BOM、动库存等），**保留**查询、查看、导出 |
| `expired` / `revoked` | 启用限制（同上；`revoked` 为平台主动吊销，无宽限期） |

> 关键点：**是否限制完全由机器端判断**，服务端只负责如实下发状态与时间，不做任何阻断。断网时沿用本地缓存的最后一次结果（纯本地逻辑）。

## 二、心跳响应新增两个字段（已在生产上线）

`POST https://heartbeat.ziwi.cn/api/v1/heartbeat` 的响应新增：

| 字段 | 类型 | 含义 |
|---|---|---|
| `license_since` | ISO8601 或 `null` | 本条授权记录的起始时间。`none` 记录即"首次上报、运营尚未建档"的时刻 |
| `grace_until` | ISO8601 或 `null` | **仅 `none` 态下发** = `license_since` + 宽限天数（默认 30）。非 `none` 态为 `null` |

响应示例（生产实测，2026-10-07）：

```json
// 已授权租户（mfg-staging）
{"status":"ok","license_status":"active","expires_at":"2026-12-31T00:00:00",
 "revoked":false,"license_since":"2026-10-07T01:45:24+00:00","grace_until":null}

// 未建档租户（none）——宽限期 = 2026-07-27 + 30天 = 2026-08-26
{"status":"ok","license_status":"none","expires_at":null,
 "revoked":false,"license_since":"2026-07-27T06:55:01.806000+00:00",
 "grace_until":"2026-08-26T06:55:01.806000+00:00"}
```

## 三、客户端实现要点（伪代码）

```python
# 每次心跳返回后，落库到本地（断网兜底：沿用最后一次成功结果）
lic_status  = resp.get("license_status")
grace_until = resp.get("grace_until")   # 可能为 None
revoked     = resp.get("revoked", False)

restricted = False
if lic_status in ("expired", "revoked"):
    restricted = True                      # 无宽限期
elif lic_status == "none":
    if grace_until and datetime.now(tz) >= parse(grace_until):
        restricted = True                  # 宽限期已过
    else:
        restricted = False                 # 宽限期内
        show_float_hint(days_left=(parse(grace_until) - now).days)   # 小窗浮层提醒
else:                                       # active / trial / 未知
    restricted = False

enforce_write_restriction(restricted)       # True 时拦截新建/修改，保留读与导出
```

**浮层提醒文案建议**（不要阻断操作）：
> 「当前部署尚未开通授权，功能可继续试用；请在 {grace_until 日期} 前联系运营完成开通，逾期后将限制新建与修改。」

## 四、可配置项

| env | 默认 | 说明 |
|---|---|---|
| `HEARTBEAT_LICENSE_GRACE_DAYS` | `30` | 未授权宽限天数；设 `0` = 无宽限，`none` 立即限制 |

## 五、兼容性

- **纯增量**：新增两个可选字段，原有 `status` / `license_status` / `expires_at` / `revoked` 语义不变。
- **旧客户端不受影响**：忽略未知字段即可（Python SDK 用 Pydantic 会忽略；Go 用 JSON 解码需容忍未知字段）。
- **服务端不采信客户端自报的 `license_status`**，一律以服务端权威态下发（原有原则不变）。

## 六、验证方式（接入方可自测）

```bash
# 需要 heartbeat 后台的 API Key（X-Api-Key），由运营方提供
curl -sS https://heartbeat.ziwi.cn/api/v1/heartbeat \
  -H "X-Api-Key: <KEY>" -H "Content-Type: application/json" \
  -d '{"tenant_id":"<你的租户ID>","product":"mfg","version":"1.0.0"}'
```
预期响应包含 `license_status` 与 `license_since`；若为 `none` 还会包含 `grace_until`。

## 七、归属与边界

- 本规则为 **cloud 运营端（心跳服务端）** 的下发语义，实现方（客户端门禁与浮层）属 **各产品线自己的代码**：mfg 侧由 mfg 团队实施，school 侧由 school 小组实施。
- 服务端**不做**任何阻断，也不判断客户端功能权限；它只回答"当前授权状态、龄期、宽限截止"。
- 唯一真实租户 `ecms-dna`（德耐尔，`dna.ecms.ziwi.cn`）走 **cloud 侧 B 服务**（`cloud.ziwi.cn/api/v1/platform/heartbeat`），本说明针对 **A 服务**（`heartbeat.ziwi.cn`）。B 侧字段待心跳归一时同步（见 §归一方向）。
