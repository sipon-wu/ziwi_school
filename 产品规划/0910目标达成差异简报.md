# 0910 目标达成差异简报

> 主题：把"由 Skill 生成 PPT / H5（含模板引用）"的**目标效果**与**平台实际开发现状**逐条比对，定位差距。
> 方法：先实查代码取证，再结合用户实测反馈分析。
> 配套：《0910模板方案》（目标态设计）；《课件与课件风格-需求汇总》《会话需求提取》（需求侧）。
> 日期：2026-09-10 ｜ 结论口径：只陈述代码里"实际有什么/没有什么"。

## 一、结论速览

| 维度 | 目标 | 现状 | 达成度 |
|---|---|---|---|
| Skill 编排 | 由 Skill 按 S0–S5 生成 | 单次 LLM 调用，SKILL.md 仅作文本注入 | ❌ 未达成 |

## 二、平台功能开发现状（代码实查证据）

### 2.1 "Skill 生成"名不副实 —— 只是把 Skill 文本拼进 prompt

- `/api/ai/courseware/generate` 实现在 **Python FastAPI**：`code/ai-service/api_server.py:509`；Go 侧仅反向代理（`code/backend/cmd/server/main.go:229-241`）。
- 生成 = **一次性 prompt + 单次 LLM 调用**（`api_server.py:790-800`，模型 qwen-turbo），**无 S0–S5 编排、无质检回环、无工具调用**。
- SKILL.md 本体**未被加载**；只读取其 `references/` 与 `shared/质量宪法.md` 当提示词文本：
  ```480:484:code/ai-service/api_server.py
  _SKILL_REFS = {
      "ppt": ("shared/质量宪法.md", "courseware-ppt/references/版式与组件选型.md"),
      "h5": ("shared/质量宪法.md", "courseware-h5/references/场景与互动规范.md"),
  }
  ```
- 工具 `template.query / asset.search / slide.render / visual.check / story.render` —— **全库仅出现在 .md 与 SKILL.md 中，无任何可执行实现**（grep 证据：命中文件全是文档）。

### 2.2 风格参数链路 —— 半通

- `generate` 收 `style_tag / style_profile / style_mode`（`api_server.py:538-545`），但 **不读 `theme_id`**；`style_mode` 读了却无分支使用。
- 返回含 `style_tag / style_profile / color_palette`，**不含 `theme_id`**（theme_id 由前端本地 `defaultThemeForStyle` 决定，`CoursewareBuilder.tsx:667-669`）。
- 已做的关键修复（2026-09-03）：
  - `_load_style_layout_language(style_tag)` 真读风格卡「骨架形态语言」段注入 prompt（`api_server.py:914-932`）。
  - `_courseware_palette` 按风格派生色相，`_STYLE_HUE`/`_STYLE_MORPH` 8 种风格角距 ≥25°（`api_server.py:892-908, 948+`）。

### 2.3 H5 渲染 —— 形态已打散，皮肤表却有硬伤

- 皮肤表 **只有 4 键**：`storybook / forest / night / ocean`（`code/frontend/src/lib/courseware-h5/types.ts:168-181`）。
- 库内实际 `theme_id` 是 **CwTheme id**：`zgf-ink-wash / te-quantum-blue / fr-mint / aca-edu-blue / sp-cartoon / min-classic-blue`（`qa/h5_owner_map.tsv` 实测）。
- 解析回退逻辑：
  ```32:35:code/frontend/src/lib/courseware-h5/renderer.ts
  function resolveStoryTheme(colorRoot: unknown, themeId?: string): typeof STORY_THEMES[string] {
    const base = STORY_THEMES[themeId || 'storybook'] || STORY_THEMES.storybook
    const sd = parseStyleDNA(colorRoot)
    if (!sd) return base
  ```
  → CwTheme id 命中不了皮肤表，**颜色回落 storybook**；**仅当 `colorRoot`(styleDNA) 有效时才恢复专属配色**。
- 前端已做**前缀补偿**（形态层面打散）：`STYLE_PREFIX_MORPH`(renderer.ts:79-87)、`STYLE_PREFIX_LAYOUT`(98-107) 按 `fr-/zgf-/te-/min-/aca-/sp-` 前缀给疏密/动效/母题/骨架类。**但颜色仍趋同**（无 styleDNA 时）——这与用户"还有一样头面"的观感一致。
- 场景骨架**已差异化**但非全覆盖：`renderer.ts:320-352` 有 `sk-read / sk-quiz / sk-draw / sk-phenomenon`；`dialog / transition / focus / reveal` 仍共用轻量骨架（注释自认是"避免过度设计"的收敛）。

### 2.4 PPT 渲染 —— 槽位模型已实现（部分）

- `code/frontend/src/lib/cwTemplate.ts`：`distributeToSlots`(511)、`remapSlots`(557)、`applyTemplate`(1179) 已按 placeholder key 重映射内容（1201-1203）。
- `PptxPreview.tsx:708` 已读 `s.slots`；但 766/784/797/798/834 仍保留 `lines[0]/[1]/[2]` **行号硬编码回退**（部分版式未收口）。

## 三、目标效果（前面对话已确立）

1. 主目标 = **优化课件 UI 风格**（换肤 / 骨架 / 形态），**不是重新生成内容**。
2. 由 **Skill 生成**，模板"只提供风格语汇与可引用资产，不提供结构"。
3. 风格 **styleDNA 快照**进课件，渲染只读快照、不读 template_id。
4. 用户原话（被 `renderer.ts:92` 引用）：**"不要变点颜色换点 SVG 图标就表示不同风格"**。
5. 09-03 定案：**已发布课件不可原地改**，只借生成新版本（草稿）。

## 四、差异分析（逐条）

| # | 目标 | 代码现状 | 差距性质 |
|---|---|---|---|

### 4.1 决定性 bug：生成 H5 时用了**旧的 themeId / 旧的 colorRoot**

`CoursewareBuilder.tsx` 中 AI 生成流程：
```599:640:code/frontend/src/pages/CoursewareBuilder.tsx
setColorRoot('') // 新生成走 theme_id 兜底，清掉旧课件的 styleDNA
...
if ((res as any).color_palette) setColorRoot(JSON.stringify((res as any).color_palette))
if (isH5 && res.courseware_markdown) {
  setCwH5Html(markdownToStorybookH5(res.courseware_markdown, {
    ... themeId: themeId,
    colorRoot: colorRoot,      // ← 此处仍是闭包里的旧值/空值
  }))
```
- React `setState` 异步：第 599/633 行的 `setColorRoot` 与第 663/667/669 行的 `setThemeId` **都在 636-640 渲染之后才生效**。
- 结果：**刚生成出来的 H5 快照用的是旧主题、旧(空)styleDNA** → 视觉上"还是老样子"。
- 发布时若 `cwH5Html` 已存在则**直接复用该旧快照**（`CoursewareBuilder.tsx:933`），缺陷被固化。

## 五、用户实测反馈分析

**反馈事实**（截图）：打开 3 个课件（`观潮_风格对照_tech`、`观潮_风格对照_china`、`分数的意义_H5课件(新版生成)`），页面只显示封面标题 + 一句"画面描述：…"，且"还是一样的头面"。

**根因拆解（两层，须分开定性）**：

1. **操作事故层（我的错，非平台缺陷）**：这批内容是错误脚本 `qa/batch_regenerate.mjs` 产生的——它以**空 `content`** 调 generate，模型只能吐出"封面画面描述"；且脚本用 **`PUT` 覆盖了原件**，违反 09-03 定案。**这不是平台生成链路的正常产物。**
2. **平台缺陷层（真实存在）**：即便链路正常，"头面一样"仍有代码级根因：
   - **G3**：H5 皮肤表与 CwTheme id 不对齐 → 无 styleDNA 时颜色一律回落 storybook；
   - **G4**：生成即渲染的时序 bug → 新皮肤/新配色没进快照。

**附带问题**：所选 3 个是"风格对照测试件"，并非用户真正要优化的目标（用户明确"其中还有一个是 H5"，说明混有非 H5 格式）。**试点对象选择本身就是错的。**

## 七、纪律复盘（红线）

1. 优化风格 = **保留原内容，只换皮肤/骨架**；不得以空 `content` 驱动生成。
2. **绝不 `PUT` 已发布原件**；只 `POST` 新建草稿（09-03 定案）。
3. 试点先**小批量、可核对**；目标课件由用户指定，不擅自替选。
4. 改动先 staging 验证，不自动上生产。
