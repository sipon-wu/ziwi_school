# 平台运维（platform_devops）核心交互流程图

> 版本：v1.0 | 日期：2026-07-04 | 作者：小艺（UI/UX设计师）
> 依据：产品功能规格说明书 0703-v6 + 架构设计 v3.1 + 二期设计稿（系统监控大盘）

## 一、角色定位与入口

```
平台运维 = 独立登录态 + 运维 Dashboard + 全网级基础设施管理

权限矩阵：
├── monitor:* （系统监控）
├── log:* （日志管理）
├── performance:* （性能管理）
├── security:* （安全管理）
└── backup:* （数据备份）

侧边栏：
  系统监控 / 日志管理 / 性能管理 / 安全管理 / 数据备份 / 告警配置

特点：全网级，跨学校，不涉及财务操作，专注于系统稳定性
```


## 十、加载态规范

> 小Q验证反馈：平台运维缺失加载态。本节补充4个核心场景。

| 场景 | 加载态表现 | 降级方案 |
|------|----------|---------|
| 监控大盘加载 | 5个服务指示灯骨架屏 + 4个核心指标卡片骨架屏 + 2个趋势图骨架屏 | 加载失败→ErrorState + 「重新加载」按钮 |
| 日志查询加载 | 日志列表骨架屏（表格占位，表头+10行数据行） | 超时→提示「缩小时间范围后重试」 |
| 性能数据加载 | 图表骨架屏（折线图+面积图占位） | 加载失败→显示上次缓存数据 + 「刷新」按钮 |
| 备份状态刷新 | 状态卡片骨架屏（备份概览4个指标占位） | 加载失败→显示上次备份时间 + 「重试」按钮 |

## 十二、异常路径

### 服务宕机
```
场景：核心服务（API/AI/DB）宕机
  → 系统监控大盘红色指示灯闪烁
  → 立即推送告警到运维人员微信
  → 自动触发故障排查SOP
  → 知了可提供故障排查建议
```

### 备份失败
```
场景：自动备份任务失败
  → 告警通知运维人员
  → 备份管理页显示失败标记 + 失败原因
  → [重试备份] 或 [手动触发备份]
```

### 安全事件
```
场景：检测到异常登录或API滥用
  → 安全管理页红色高亮标记
  → 自动推送告警
  → 运维人员可强制下线/封禁IP
```

### 数据为空
```
场景：监控数据缺失（如Prometheus未采集到数据）
  → 服务状态显示灰色未知
  → 提示：「监控数据采集异常，请检查Prometheus配置」
```

### RTO超时
```
场景：数据恢复时间超过2小时RTO目标
  → 进度条显示红色预警
  → 自动通知运维负责人
  → 记录超时原因到灾难恢复报告
```
