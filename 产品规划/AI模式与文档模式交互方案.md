| 用户提问 | 结论 |

## 2. 问题一：AI 模式的生成触发机制（UE 主张）

### 2.1 心智模型：一条主线，三处入口，一个动作

```
知识图谱选点 ──┐
左栏参数     ──┼──→ ［生成参数池］──→ 〔一个动作：AI 生成〕──→ 作品 → 自动进【预览页】看效果
小微对话     ──┘                          ↑                    （预览内可继续小微会话；退出回原模式；或切文档模式所见即所得编辑）
                                    三处入口都指向它
```

**三处入口（同一动作，不同触发位）**：
- **入口 A（推荐主路径）**：小微面板底部主按钮 —— 文案由「应用到当前内容」改为 **「✨ 生成课件」**（按场景变名：生成教案 / 生成习题 / 生成试卷 / 生成课件）
- **入口 B**：左栏底部主按钮（现有），**doc 模式也常驻**，文案随态变化
- **入口 C**：知识图谱面板选完点后浮出「已选 N 个知识点 · 去生成」轻提示条（点了滚动定位到主按钮并高亮，不直接生成）

### 2.2 小微面板升级为「生成驾驶舱」

小微面板底部新增一条**参数就绪条**（不是新面板，是现有面板底部加一行）：

```
┌─────────────────────────────────────────┐
│ 小微 · 补充需求                      ⌄  │
├─────────────────────────────────────────┤
│  （对话区，保持现状）                    │
├─────────────────────────────────────────┤
│ 已就绪：课题✓ 知识点 6✓ 需求 3 条✓      │  ← 新增：参数就绪条
│ [ ✨ 生成课件 ]              [ 继续补充 ] │  ← 主按钮改文案
└─────────────────────────────────────────┘
```

- **就绪条**实时反映生成参数池：课题名称 / 已选知识点数 / 已收集需求条数 / 已答问诊数
- 缺必填（课题为空 或 知识点为 0）时主按钮**置灰**并提示缺什么，杜绝"点了没反应/报错才知道"
- 小微对话里 AI 主动问"已收集 X 条要求，是否现在生成？"（prompt 第 4 条已写），用户回"生成"时，**小微回复内嵌一个行内生成按钮**（可选增强，P1）

### 2.3 不做自动触发（克制）

明确**不做**"说完自动生成"：AI 生成有 token 成本 + 15~35s 等待 + 会覆盖已有内容，必须由人显式按下。这是克制红线，不是能力缺失。

## 3. 问题二：切文档模式时加载 AI 成果

### 3.1 数据契约：单一内容源

```
              唯一内容源（页面级 state，落库同一列）
教案   → content(HTML)
出题   → questions[]
组卷   → sections[]
课件   → cwOutline[] (+ cwH5Html for h5)
```

- **AI 模式与文档模式共用同一份内容源**，模式只决定"用哪个外壳编辑它"，不复制、不双份
- 生成成功 → 写内容源 → **自动进【预览页】让用户看效果**（默认落点不再是文档模式，见问题五 5.3）；文档模式则所见即所得加载同一内容源供编辑

### 3.2 文档模式 = 所见即所得加载当前作品

文档模式不是"另一种内容"，而是**把当前唯一内容源以所见即所得外壳渲染、可直接编辑**：

- 进入文档模式 = 加载当前作品内容到 WYSIWYG 编辑器（课件=提纲画布、教案/试卷=TipTap 富文本），用户在此做人工编辑
- 人工编辑后内容源即更新；切回 AI 模式按问题三把人工稿喂回 AI

### 3.3 三种进入文档模式的路径，统一行为

| 路径 | 内容源状态 | 文档模式表现 |
|---|---|---|
| 从预览/AI 模式手动切到文档模式 | 有内容 | 直接渲染当前作品、可编辑 ✅ |
| 用户手动点「文档模式」标签（还没生成） | 空 | **空态引导页**：「还没有内容。可切到 AI 模式让小微生成，或直接从空白开始编辑」+ 两个按钮 |
| 打开已有草稿/已发布件 | 有内容 | 渲染库里的内容（现状已满足） |

**当前缺口**：空态引导没有，课件页显示的是干巴巴的"课件内容为空，请先生成课件"（CoursewareBuilder.tsx:1502），没给出路。需补两个行动按钮。

## 4. 问题三：人工编辑后切回 AI 模式

### 4.1 两个铁律（互补）

- **铁律 A（防丢）**：AI 永不静默覆盖人工劳动。
- **铁律 B（养料）**：人工编辑后切回 AI，应把人工成果喂回 AI，支持**交替优化**（human-AI co-iteration）。

两律合起来才是完整语义：既不让人的劳动被冲掉，也不让 AI "假装人工没发生过"。

### 4.2 时间冲突：用「生成锁」堵死，不用时间戳

AI **生成进行中，禁止切换文档模式**（文档模式入口禁用/只读，生成完成才解锁）。因此不存在"人工改到一半 AI 回包覆盖"的时间竞争，**不需要就后不就前的时间戳比较、不需要 cancel 旧任务**。这跟现有 loading 态自洽，仅补"锁住模式切换"一条。

### 4.3 交替优化：人工稿作为 `prev_content` 回填

切回 AI 模式时，当前文档内容（无论 AI 产出还是人工改过）**整稿回填为生成接口的 `prev_content`（或 `base_content`）**：

```
需求(首轮) → AI生成 v1 → 人工改 v1.5 → 切回AI时把 v1.5 回填 prev_content → AI生成 v2(基于v1.5，非v1)
```

- 后端 `/api/ai/courseware/generate` 增可选字段 `prev_content`：有则"在基础上优化"，无则"从需求生成"
- 主按钮文案随态变化：**首轮「✨ 生成课件」** → **后续「✨ 基于当前优化」**（明确表达"迭代"而非"推翻"）
- **整稿回填即可覆盖 90% 交替优化价值**；逐操作 diff 记录留 P2（仅当要做"AI 解释我为什么这样改"时才需 patch 级上下文）

### 4.4 指令冲突：AI 出变更预览，逐条确认（核心仲裁机制）

真正的冲突是**指令冲突**（非时间）：人工删了某页（指令：不要这页），AI 基于旧稿又想强化这页（指令：补强这页）。不能甩给用户读全文 diff（认知负担爆炸），改为**让 AI 先自报要动哪**：

```
切回AI → 把 人工稿 + 原始需求 一起发给后端做「变更预览」（不落地）
  → 小微面板展示：我打算做这几处改动（每条标注 修改/保留/还原了你删除的X）
  → 用户逐条勾选 采纳/拒绝 → 才真正生成
```

- 冲突项（如"恢复你删除的 X 页"）**显式标红提示**，用户一眼看到 AI 想推翻自己的操作
- 这复用问题三 4.5「AI 局部润色」的逐条 UI 能力，不是新东西
- 因此"二次确认"从**二元（生成/不生成）升级为三元（逐条采纳）**

### 4.5 切回 AI 模式的分支表

引入页面级标记 `humanEdited`（文档模式任一编辑动作 → true；AI 生成成功 → false）：

| `humanEdited` | 切回 AI 模式的表现 |
|---|---|
| false（AI 刚生成，没动过） | 正常进 AI 模式，主按钮 = 「重新生成」，点了直接覆盖（无害，覆盖 AI 自己产物） |
| **true（人工改过）** | 进 AI 模式，主按钮变 **「✨ 基于当前优化」**；AI 基于人工稿出**变更预览、逐条确认**（见 4.4）；黄条降级为「将在你改动基础上优化」，不再吓唬"覆盖" |

> 教案页已有覆盖确认（LessonPlanEditor.tsx:761 `showAiConfirm`），本方案**提到框架层，五页统一**，并把"全量覆盖确认"升级为"变更预览逐条确认"。

### 4.6 提供非覆盖的第二条路 + 版本安全带

- **「AI 局部润色」** —— 不覆盖，把小微需求作用在**选中段落/选中页**上，只替换局部（教案页已有「AI 润色」雏形，课件页有「AI 润色提纲」）
- 执行任何"覆盖式"重写前，**自动 flush 一次草稿并打版本点**（课件/教案已有版本栏 `cwHistoryVisible`），用户后悔可回退

## 5. 问题四：保存草稿 / 预览 / 发布 的状态响应

### 5.1 总纲（用户判断正确，本方案照此落地）

> **任何切换都就当前状态保存进草稿。**

具体到实现：**模式切换（AI↔文档）、频道切换（PPT/H5/视频）、打开预览、离开页面 → 一律先 `ctrl.flush()`（静默存草稿，不弹 toast）**。失败静默（不阻断切换），文档模式内仍可手动保存。

**新建态落库策略（已拍板·方案 b）**：切换 flush 时，若当前**尚无 materialId（新建态）**，只写 `localStorage` 草稿兜底，**不立即在库里创建草稿记录**；唯有用户显式点「保存为草稿」或生成成功落库后，才分配 materialId 并写库。理由：避免用户随手切两下模式就污染草稿库（课件页本就有 localStorage 兜底，与此一致）。已有 materialId 的 flush = update，正常落库。

### 5.2 预览 = 各编辑模式的共享出口，只用于看效果

**编辑态的两种并列模式（必须先分清，避免术语混淆）**：
- **AI 模式（会话式编辑）**：也是编辑模式，只是编辑方式是"和小微对话"——下达指令、AI 改写作品。它**不叫"非编辑"**，它就是编辑态的一种。
- **文档模式（所见即所得编辑）**：另一种编辑模式，编辑方式是带编辑器的直接改。
- 两者**并列、都是"编辑态"**，区别仅在编辑手段（会话 vs 编辑器），不区别"是否编辑"。

**核心路由铁律：从哪个编辑模式进预览，退出就回哪个编辑模式。**
- 预览是一个**叠加在两种编辑模式之上的共享查看层**，作用单一——**展示当前作品的呈现效果**，不承载任何编辑或会话能力
- **从 AI 模式进预览 → 退出回 AI 模式**（可继续会话式编辑）
- **从文档模式进预览 → 退出回文档模式**（可继续所见即所得编辑）
- **从查看态进预览 → 退出回查看态**
- 进入前统一先 `flush()`；**绝不可"统一回某个编辑模式"**——那会丢失用户原本所在的编辑上下文

- **预览内无小微入口、无编辑器**：预览是纯查看层，不能在预览里唤起小微或改内容；要修改必须退出预览，回到进入时所属的那个编辑模式
- **生成完成的默认落点 = 预览页**：从小微（AI 模式）发起生成、成功后**直接落到预览页**，让用户先"看效果"；因是从 AI 模式进入，退出预览**回到 AI 模式**，可继续会话式编辑提修改意见

> 这一铁律消除了此前"生成完自动跳文档模式、然后呢？"的断点：生成完先给预览看效果，看完退出回 AI 模式（原编辑模式）继续聊，而非被强行丢进文档模式。

**是否重新生成，由小微 AI 根据会话自行决定**：用户在 AI 模式（会话式编辑）基于预览看到的效果提修改意见，小微 AI 自行判断该"在现有基础上优化"还是"重新生成"——系统不强制二选一，也不在 UI 上硬性分流"优化/重生成"按钮（问题三的「✨ 基于当前优化」主按钮仍保留为显性入口，但 AI 会话路径下以 AI 自主决策为准）。

### 5.3 三按钮语义表

| 按钮 | AI 模式（未生成） | AI 模式（已有内容） | 文档模式 | 查看态（只读） |
|---|---|---|---|---|
| **保存为草稿** | 置灰（无内容可存）+ tooltip「请先生成或输入内容」 | 可用：存参数+内容，落库 `status=draft` | 可用：存内容，落库 draft | 变「编辑」 |
| **预览** | 置灰 + tooltip「请先生成内容」 | 可用：**先 flush → 开预览（退出回 AI 模式）** | 可用：**先 flush → 开预览（退出回文档模式）** | 可用（全屏放映，退出回查看态） |
| **发布** | 置灰 | 可用：flush → 红线校验闸 → 通过则 `status=active` | 同左 | 变「返回库」 |

### 5.4 状态机与视觉反馈

沿用 `useEditorLifecycle` 的 `EditorStatus`：

```
unsaved ──touch──→ (debounce 8s) ──→ autosaving ──→ draft ──publish──→ published
   ↑                                                   │
   └────────────── touch（再改动）←────────────────────┘
```

footer 左侧统一显示状态微文案（现无，需补）：
- `unsaved` → 「未保存」（灰）
- `autosaving` → 「保存中…」（转圈）
- `draft` → 「草稿已保存 · 14:32」（灰）
- `published` → 「已发布」（绿）

### 5.4 边界规则

1. **模式切换不弹保存确认框**——静默 flush 即可，弹框是认知负担（克制红线）
2. **flush 失败不阻断切换**——只在 footer 状态位显示「未保存」，不打断用户
3. **发布后再编辑**：`published` 状态下 touch → 回落 `draft`（已实现，useEditorLifecycle.ts:48），需要在 UI 上提示「已发布件被修改，需重新发布生效」
4. **已定版发布**（教案 finalize）→ 保存草稿按钮禁用（已实现）

## 6. 与 PPT/H5 频道的关系（回应上一轮"夹杂 PPT 痕迹"）

本方案确立：**生成阶段同构，产出后分叉**。

| 阶段 | PPT | H5 | 视频 |
|---|---|---|---|
| **AI 模式（左栏+知识图谱+小微+主按钮）** | 完全一致 | 完全一致 | 完全一致 |
| 生成参数差异 | `format='ppt'` | `format='h5'` | `format='video'` + videoConfig |
| **文档模式（编辑外壳）** | 提纲+画布+版心+模板库 | 提纲页 + 每页互动组件（V2.2 组件化） | 提纲 + 视频配置面板 |
| 预览 | PPT 放映 | iframe 运行态 | 分镜预览 |
| 导出 | PPTX/Word/PDF | HTML | （待 token 平权） |

因此需从 h5 频道**移出**的 PPT 专属控件（仅在 ppt 频道显示）：发散度、边缘知识、课前问诊、风格模板、参照课件、16:9 版心、模板库、+页。

> 注：发散度/边缘知识是"受控发散"模型的 PPT 课件控件（见《课件边界约束模型》），H5 绘本走独立 prompt，不需要这套。

## 附：本方案未涉及（明确不做）
- 不做"对话完自动生成"（token 成本 + 覆盖风险）
- 不做 AI 模式下的内容直接编辑（AI 模式只攒参，编辑一律在文档模式）
- **不做预览内会话/编辑**：预览是纯查看层，无小微入口、不能改内容；要修改必须退出预览回到编辑模式（见 5.2）
- 不做多版本 AI 结果并排比较（复杂度高，无验证需求）
- 不改 `EditorLayout` 的两标签固定语义（框架铁律：AI 模式 / 文档模式；预览是叠加在两者之上的共享全屏层，不新增第三个模式标签）
