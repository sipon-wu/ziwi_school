# 模板资产域架构与计价抽象层方案

> 版本：V1.0　起草：2026-08-13　状态：已拍板（待落地）
> 续篇：`AI生成课件风格模板方案.md`（风格语义层），本文聚焦"模板如何作为独立资产域治理、计价如何抽象"。

## 0. 核心结论（一句话）

**模板从"前端功能模块"沉降为"独立资产域"：所有模板（官方公共 / 平台精品 / 用户版权）都是同一张 Registry 里的一条记录，统一带 `source` 与 `base_cost` 两个字段；差异只折叠进这两个字段的取值，不在流程/数据结构/渲染路径上分叉。计价单位抽象为 `CostUnit`，用户可见词当前为 `token`，远期可换"微币/词元"而逻辑零改动。**

---

## 1. 设计动机（来自用户拍板）

1. **模板可独立增补，不依赖 school 主流程发版**——模板库是独立可演进资产域，school 只是消费者。
2. **运营端要有"增量纳入规则"**——新模板不是直接生效，而是经过注册/审核流程进入可用池，由平台运营维护（即使现在免费也是独立库、由运营维护）。
3. **远期：用户上传/编辑的模板，经平台审核 → 可定价 → 纳入模板交易**（本期不含，预留可行性）。
4. **计价用 token/积分内循环，避免在线支付交易**；精品与用户版权模板有偿（token 或积分折算），公共模板计价为 0，二者走同一模型。
5. **定价模型归抽象层**：具体单位（token）先落地，远期由运营端"知了"助手根据综合情况动态定价；定价是策略函数，不应泄漏到消费层。

---

## 2. 四层架构（自上而下，松耦合）

```
┌──────────────────────────────────────────────────────────┐
│ ① 运营治理层（后端 + ITAdminPage / ReviewPool）            │
│    - 模板注册/纳入/下架（增量规则）                       │
│    - 审核工作流（用户上传→平台审核→定价→交易）[预留]      │
└───────────────────────────┬──────────────────────────────┘
                            │ 注册/查询（按 templateId+version 寻址）
┌───────────────────────────┴──────────────────────────────┐
│ ② 模板注册中心 TemplateRegistry（权威清单）               │
│    - 记录：id/version/source/base_cost/status/owner_id    │
│    - 模板定义 JSON 存放（静态资产 / OSS，不认识 pptThemes）│
└───────────────────────────┬──────────────────────────────┘
                            │ 拉取 JSON 清单（构建期或运行期）
┌───────────────────────────┴──────────────────────────────┐
│ ③ 适配器层 lib/templateRegistryAdapter.ts                 │
│    - 唯一翻译点：模板定义 JSON → CwTheme / PPT_TEMPLATES   │
│    - 透传 source/base_cost；字段校验 + 失败隔离            │
└───────────────────────────┬──────────────────────────────┘
                            │ 输出兼容现有 applyTemplate 结构
┌───────────────────────────┴──────────────────────────────┐
│ ④ 消费层 CoursewareBuilder → applyTemplate → export       │
│    - 完全不变，只认 PPT_TEMPLATES 结构 + 读 CostUnit       │
└──────────────────────────────────────────────────────────┘
```

**耦合纪律**：
- 子项目（风格模板子项目/）独立仓库、独立 `generate.js`，**永不 import school 代码**。
- school **永不 import 子项目代码**；唯一桥梁是子项目产出的 JSON 清单（带 `category/version/templateId/tags/theme/layouts/source/base_cost`）。
- 适配器是唯一的"失败隔离"边界：坏模板 `console.warn` + 跳过，绝不抛错中断主链路。

---

## 3. 一致性内核：三来源统一于 `source` + `base_cost`

| 来源 | `source` | `base_cost` | 谁提供 | 上架动作 |
|------|----------|-------------|--------|----------|
| 官方公共模板 | `official` | `0` | 平台（子项目工厂产） | 运营"纳入"（默认全纳，计价 0） |
| 平台精品模板 | `official` / `curated` | `>0` | 平台精修 | 运营审核+定价后纳入 |
| 用户版权模板 | `user_contributed` | `>0` | 教师/第三方 | 上传→审核→定价→纳入 |

**关键点**：
- 免费不是"绕过治理"，而是"治理后 `base_cost=0`"。所有模板都走"运营纳入"动作。
- 数据结构一致：无"免费表/付费表"之分，只有一条记录上 `base_cost` 是 0 还是正数。
- 消费路径一致：`applyTemplate` 不关心来源，只关心"可用与否、要扣多少 CostUnit"。

---

## 4. 计价抽象层（CostUnit）

### 4.1 抽象原则
- 消费层只认抽象额度 `CostUnit`（数值），不知道自己叫 token / 微币 / 词元。
- 用户可见词由 `UNIT_LABEL` 常量控制（当前 `'token'`，远期 `'微币'` 仅改此常量）。
- 定价是策略函数 `price(t, ctx) -> CostUnit`：
  - 本期最简：`price(t) = t.base_cost`（运营在 Registry 填，官方模板填 0）。
  - 远期：调"知了"运营助手，综合来源/频次/学校套餐/活动折扣算出 `CostUnit`，消费层无感。
- 激励侧（用户模板被用返 token）同理——本期 `source` 永远非 `user_contributed`，返利分支留空。

### 4.2 抽象层接口（落 `lib/costUnit.ts`）
```
CostUnit            额度抽象类型（number，单位无关）
UNIT_LABEL          'token'（展示常量，可全局改）
price(t, ctx?)      定价策略（本期返回 t.base_cost）
authorize(t)        消费层统一调用：本期恒放行，远期做余额校验/扣减
```

**核心纪律**：`CoursewareBuilder` / `applyTemplate` / 模板面板——永远只 import 抽象层 `CostUnit` / `authorize` / `price`，**绝不出现 `token`/`积分`/`price_token` 具体字眼**（展示文案除外，走 `UNIT_LABEL`）。

## 5. 本期落地切片（克制，不铺开）

按最小改动集 + 证据驱动，本期只做 PPT 侧端到端打通 + H5 字段预留：

1. **子项目**：JSON 约定补 `source` + `base_cost`（官方模板 `source:"official"`, `base_cost:0`）；加 `npm run manifest` 合并散落 JSON 为单一 `template-library.ppt.json`，deploy 时 rsync 进 `code/frontend/src/assets/template-library/`。
2. **抽象层**：`lib/costUnit.ts`（`CostUnit` + `UNIT_LABEL='token'` + `price`/`authorize`，`authorize` 本期恒放行）。
3. **适配器**：`lib/templateRegistryAdapter.ts`（子项目 JSON → `CwTheme`/`PPT_TEMPLATES`，透传 `source`/`base_cost`，失败隔离；只加载 `status=active`）。
4. **消费层**：`CoursewareBuilder` 模板面板读 `source`/`base_cost` 字段，本期不触发任何计费 UI（仅预留取数）。
5. **运营端**：`ITAdminPage` 新增"模板管理" tab，列出待纳入/已纳入，接增量规则（同 templateId 仅允许更高 version 覆盖；`tags.style` 必须命中主链路 `StyleTag` 枚举否则退回）。
6. **H5 侧**：同步补 `source`/`base_cost` 字段约定，但本期只接"风格标签"用于分类，不接真内容、不接付费。

**不在本期范围**：后端 `TemplateRegistry` 表与 API（先用静态资产 + 本地 JSON 清单，deploy.rsync 即可）；付费扣减/返利逻辑；知了动态定价；用户上传 UI。

## 6. 远期预留接缝（本期仅钉结构，不实现）

- Registry 记录预置 `owner_id`（贡献者，本期空）、`price_plan`（定价/套餐标识，本期 null）。
- 适配器读 `source`：未来 `user_contributed` + `price_plan` 非空时自动挂"授权/付费"UI，本期所有模板 `official`+`null`，表现与现在完全一致。
- `ReviewPool` 可复用为审核入口（用户上传模板的审核池），本期不接逻辑。

## 7. 与既有拍板的关系

- 复用 `cwTemplate.ts` 的 `applyTemplate`/`revertTemplate` 换肤机制、`StyleTag`/`SlideLayout` 维度——子项目 JSON 的 `tags`/`theme` 映射到这些既有枚举，不另起炉灶。
- 复用 `pptThemes.ts` 的 `CwTheme` 配色——适配器把子项目 `theme.colors` 转为 `CwTheme`。
- 不破坏"零外部二进制、零版权风险"铁律（见 `AI生成课件风格模板方案.md` §0.3）：子项目模板均为程序化生成，无第三方素材。
