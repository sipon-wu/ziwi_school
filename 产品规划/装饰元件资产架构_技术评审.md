## 0. 背景与产品意图（来自用户拍板）

装饰不应是"写死的皮肤"，而应是**可组合的元件乐高**：

- **元素→元件→组件→模板→课件**：风格 = 元件（及组件）的**组合 + 排序 + 交互设定**的产物，不是预设皮肤。
- **公共库 + 个人素材库**：装饰资产分平台公共库（零依赖）与教师账号个人素材库（可上传文件，放宽零依赖红线）。
- **按学期/学科自动匹配推荐，但不限制**：系统据"学期 × 学科 × 媒介"自动推荐账号素材库内装饰，教师仍可用任意素材。
- **可抽象个人风格**：从账号素材库 + 历史选用聚类出教师个人装饰风格偏好（轻量权重/排序，非命名模板），接入既有"系统设置-训练小微"的 `StyleProfile` 沉淀。
- **AI 参与匹配与编排**：AI 据媒介/学科/学期筛选适用元件、判断组合协调性、生成组件方案。

已拍板决策汇总：
| # | 决策 | 内容 |
|---|---|---|
| ① | 个人素材库底层 | 后端账号素材库（`materials` 表，已有 UserID/SchoolID），可上传文件 |
| ② | 模板编排主体 | AI 自动编排 + 教师手动微调 |
| ③ | 元件体系媒介 | PPT + H5 共用一套资产，带 `applicable` 标签（ppt/h5/common）；组件=元件的组合；AI 参与匹配 |
| ④ | 个人素材库存储 | 后端（即 `materials` 表） |
| Q1 | 分类法 | 科学聚类分类法（层级 faceted 本体，越细越好） |
| Q2 | 个人风格形态 | 轻量推荐权重/排序偏好，接入"训练小微"StyleProfile.decor 沉淀 |

## 1. 资产模型（五层，元件/组件可并列引用）

```
① 元素 Element      最小原子：emoji / SVG 点线星 / 树叶类 / 上传图片
② 元件 Component     单件有意义装饰单元（带 facet 标签 + 交互设定）
③ 组件 Composite     元件的组合（components = 元件组合，含布局/交互编排）
④ 模板 Template      组件的组合+排序+交互 编排成果（生产端产物，经运营审核）
⑤ 课件 Courseware    消费端（Materials.tsx / H5 产出），只套用不生产
```

**关键澄清**：组件是元件的组合封装；**元件与组件都是可被课件直接引用的装饰单元**（用户确认"元件也可直接引用到课件"）。因此存储上不强制分层隔离，用 `kind` 区分：
- `decor_element`：单元件
- `decor_component`：元件组合（内含 `elements:[{asset_id, x, y, scale, rotation, z, interaction}]`）

④模板复用既有 `template-library.*.json`（增 `decor` 字段引用组件），不新建模板实体。

## 2. 科学聚类分类法（层级 faceted 本体）

每个装饰资产（①~④）带 `decor_facets` JSON：一组 facet 标签，维度内树状细分、维度间正交。母题类目做深分层；其余维度允许 AI 运行时弹性调整。

### F1 媒介适用性 `applicable`（不细分）
`ppt` / `h5` / `common`

### F2 母题类目 `motif`（层级细分，越细越好）
```
motif
├─ 自然
│  ├─ 植物 → 树叶 / 花朵 / 草木 / 藤蔓
│  ├─ 天文 → 星 / 月 / 日 / 云 / 虹
│  ├─ 动物 → 昆虫 / 飞禽 / 走兽 / 水生
│  └─ 地貌 → 山 / 水 / 石
├─ 几何
│  ├─ 点线 → 点线星 / 虚线框 / 网格
│  ├─ 形状 → 圆 / 方 / 多边形 / 不规则
│  └─ 纹理 → 波点 / 条纹 / 格纹
├─ 符号
│  ├─ 标点类 → 五角星 / 爱心 / 感叹 / 引号
│  ├─ 学科符号 → 公式 / 字母 / 数字 / 单位
│  └─ 文化符号 → 中国风 / 节庆 / 民族纹样
├─ 插画感（情景小物）
│  ├─ 场景 → 教室 / 书包 / 书本 / 文具
│  ├─ 人物 → 卡通娃 / 教师 / 学生剪影
│  └─ 道具 → 气球 / 风筝 / 灯笼
└─ 边框底纹
   ├─ 边框 → 实线 / 虚线 / 花边 / 角花
   └─ 底纹 → 渐变 / 水彩 / 噪点
```
> 此树可随业务继续下钻（如 树叶→枫/柳/松针），无深度限制。

### F3 视觉属性 `visual`
`风格`(扁平/线条/实心/渐变/手绘感/像素/水墨) · `色系`(暖/冷/中性/多彩) · `饱和度`(高/中/低) · `复杂度`(极简/中/繁复)

### F4 交互 `interaction`
`静态` · `动效`(浮动/闪烁/旋转/渐显/呼吸) · `响应`(点读高亮/悬停放大/点击展开/跟读同步)

### F5 权属来源 `source`
`public`(平台公共，零依赖) · `user_upload`(账号上传，可含文件) · `user_generated`(账号内组合生成)；`owner=user_id`

### F6 学期学科适配 `fit`（匹配推荐维度，非限制）
`grade_band`(低段1-2/中段3-4/高段5-6/初中/高中) · `subject`(语文/数学/英语/科学/…) · `season`(春夏秋冬/节庆)
> 仅用于自动匹配与推荐权重，**不限制**教师选用。

## 3. 存储设计（复用 `materials` 表，最小化迁移，不留坑）

`materials` 表已有 `UserID`/`SchoolID`/`Type`/`Format`/`Tag`/`Grade`/`Subject`/`ThemeID`/`URL`/`Content`。**新增列**：

| 列 | 类型 | 说明 |
|---|---|---|
| `category` | varchar | `decor_element` / `decor_component` / `courseware`（区分普通课件素材） |
| `decor_facets` | jsonb | 上述 6 维 facet 标签（层级路径数组，如 `["motif.自然.植物.树叶"]`） |
| `applicable` | varchar | ppt/h5/common（冗余自 facet，便于索引） |
| `motif_root` | varchar | 母题一级（冗余，便于索引） |
| `interaction` | varchar | 交互类型 |
| `parent_ids` | text[] | 组件指向其元件的 asset_id 数组 |

**防坑要点**：
- `decor_facets` 建 **GIN 索引**支持 jsonb 包含查询；同时冗余 `applicable`/`motif_root` 独立列做高频过滤，避免深 jsonb 查询性能问题。
- `parent_ids` 用数组而非关联表（组件数量有限，避免过度范式化）。
- 个人风格沉淀进已有 `users.style_profile jsonb` 的 `decor` 子键（字段已存在，仅扩解析，**零新建表**）：
  ```json
  { "decor": {
      "motif_weights": {"motif.自然.植物.树叶": 0.9, "motif.几何.点线.点线星": 0.7},
      "visual_pref": {"风格":"手绘感","色系":"暖"},
      "interaction_pref": ["浮动","点读高亮"],
      "confidence": 0.85
  }}
  ```

## 4. AI 接口契约

### `POST /api/ai/decor/recommend`（只读匹配推荐）
- 输入：`{ medium, subject, grade_band, season?, user_id }`
- 输出：`{ recommendations: [{ asset_id, facet_path, score, reason }] }`
- score = facet 匹配度（F1/F6）+ 个人 `StyleProfile.decor` 权重 + 历史选用聚类
- 职责：对应 Q2 轻量推荐，不生成新资产

### `POST /api/ai/decor/compose`（AI 编排）
- 输入：`{ medium, subject, grade_band, style_tag?, user_id, selected?:[asset_id] }`
- 输出：`{ components: [元件组合方案], layout, interactions }`
- 职责：据 facet 自动筛选 applicable 命中项、判断组合协调性、生成组件（对应 ②AI 自动编排）；可脱离推荐用手选输入
- 产出可预览 / 落库为 `decor_component`（user_generated）

## 6. 实施计划（分阶段，每阶段有验收）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 数据层** | `materials` 迁移（+category/decor_facets GIN/applicable/motif_root/interaction/parent_ids）；`users.style_profile` 扩 decor 解析；handler 支持 decor 上传/查询 | migrate 通过；POST 带 facets 落库；GET 按 applicable+motif 过滤正确 |

## 7. 评审结论与待决议项

### 已明确（用户拍板 + 技术决策）
- ✅ 五层资产模型，元件/组件并列可引用
- ✅ 层级 faceted 分类法，母题深分层，其余维度 AI 弹性
- ✅ 复用 `materials` 表 + `users.style_profile`，零新建表
- ✅ 两个 AI 接口职责分离（recommend 只读 / compose 生成）
- ✅ 公共库零依赖、个人库可上传（放宽红线，仅个人）

### 待评审决议项（评审结论：2026-08-24 按推荐批准）
1. **P0 迁移批准执行（先出迁移文件过目再执行）**：涉及后端 `materials` 表 schema 变更 + 迁移脚本（不动数据，仅加列）。✅ 批准，但迁移 SQL 需先给用户过目再执行（动库纪律）。
2. **起步范围：P0 + P1 小步验证**：先落地数据层 + 公共元件种子验证跑通，P2~P4 后续分阶段排期。✅
3. **零依赖红线边界**：个人库 `user_upload` 允许文件，H5 导出时**自动检测个人素材，有则标注"含个人素材需联网"**，避免离线打开失效。✅
4. **facet 词表治理：受控词表**：母题树由**平台运营维护**（受控词表），教师上传元件只能从受控词表选标签，不能自建，避免标签污染导致 AI 匹配失效。✅

### 技术风险提示
- `decor_facets` 深查询性能：已用 GIN + 冗余列缓解。
- 个人上传文件与"独立 H5 离线打开"冲突：已在待决议项 3 标注。
- 训练小微当前为前端模拟未落库：P3 需补后端持久化 `StyleProfile.decor`，否则推荐无据。
