# 断言与证据规范（2026-09-17）

> 立这份规范的直接原因：2026-09 的一轮开发里，同一类错误反复出现（至少 6 次），
> 每次都靠"回到证据本身"才纠正过来。**靠记性防不住，所以写成规范 + 工具 + 门禁。**

---

## 一、三类失效模式（所有误判都落在这三类里）

### A. 用局部证据下全局结论

| 实例 | 真相 |
|---|---|
| 探到「300 条节点 `unit` 全空」→ 判定"库里 KG 单元未回填" | 库里 5552 行有 5164 行有单元；那 300 条是**默认页**（`ORDER BY dan_yuan NULLS FIRST` + `limit=300`，恰好 388 行空单元霸屏）。结论错了两个数量级 |
| 探模板面板"56 个候选卡片" | 探针的祖先链遍历走到了 `#root`，于是"包含面板文案"对**所有**按钮都为真 |

**规则 A1：任何"全空 / 全对 / 全错"的结论，必须带分母**（`n/total`）。
**规则 A2：结论必须声明样本怎么来的** —— 哪个接口/查询、是否带过滤、**是否被 limit 截断**。
> 若 `返回条数 == limit`，几乎可以断定**被截断了**，此时**禁止**用该样本推断全量分布。

### B. 断言太弱，或恒真/恒假（假绿）

| 实例 | 为什么假绿 |
|---|---|
| `backgroundImage.includes('')` 判"画布已渲染素材" | 空串被任何字符串包含 → **恒真** |
| `/cover-deco/` 判"页面残留装饰" | 类名在**样式表**里恒存在 → 判的是 CSS，不是元素。应判 `<img class="cover-deco` 这种**元素形式** |
| 测试只点"含 `img` 的卡片" | 一张都没点中 → 面板没关 → 后续点「保存草稿」被遮罩拦住，于是**把"保存被拦"误读成"面板打不开"，怀疑产品** |
| 数据探针只打印结论不打印原始值 | 无法复核，错了也看不出来 |

**规则 B1：断言必须先能失败。** 写下断言时先回答"什么情况下它为假？" 答不出 → 该断言无效。
**规则 B2：禁止恒真构造**：空串参与 `includes/startsWith/indexOf`、只判类名/关键字存在、只判"没有抛异常"。
**规则 B3：判元素，不判样式表**；判**状态变化**（点击前后各取一次），不判"看起来对"。
**规则 B4：报错元件 ≠ 出错动作。** 看到 `intercepts pointer events` 之类，**先确认被拦的是我哪一步**，再怀疑产品。

### C. 门禁缺失（流程没拦住）

| 实例 | 后果 |
|---|---|
| `tsc` 与 `git commit` 串在同一条命令、**没有按退出码设门禁** | 提交了编译不过的版本（`2972c11`：只加类型、漏解构形参） |
| 部署失败（ssh 超时）却继续解读接口返回 | 用**上一个部署**的数据得出"未达预期"，差点又误判 |

**规则 C1：编译/静态检查与提交之间必须有硬门禁**（退出码非 0 就不提交）。
**规则 C2：部署/启动类动作必须先确认"这一步真的成了"**，再解读其后的任何测量结果。

## 二、落地机制（规范之外的三道锁）

### 1. 工具：`qa/lib/assert.cjs`
把"防恒真 + 分母 + 被 limit 截断告警 + 失败即非 0 退出"做成函数，脚本直接用：

```js
const { must, notEmpty, mustChange, sampled, report } = require('./lib/assert.cjs')
must(items.length === 300, '默认页条数', { got: items.length })   // 附证据
sampled(items, { limit: 300, source: 'GET /api/ai/knowledge/nodes' }) // 若 len==limit → 打印"可能被截断"告警
notEmpty(url, 'picked asset url')        // 直接挡掉 includes('') 那类错
report()                                  // 任一条失败 → 进程非 0
```

### 2. 门禁：`.githooks/pre-commit`
提交前自动跑 `tsc --noEmit` + lint，不过就拒绝提交。启用一次即可：

```bash
git config core.hooksPath .githooks      # 由你执行（我不改你的 git config）
```

### 3. 台账：结论与证据
凡是要写进汇报/提交信息的**结论**，附上：结论 → 证据命令 → 分母 → 复核方式。
本文件即台账的范式；后续新增判别性结论，追加到 `qa/结论台账.md`。

## 三、动手前的四问（贴在流程里的最短清单）

1. **分母是多少？** 我看到的 n 占全集多少？
2. **样本怎么来的？** 哪个接口/查询、有无过滤、**有没有被 limit 截断**？
3. **断言能失败吗？** 什么输入会让它变假？现在是"恒真"吗？
4. **被拦的是哪一步？** 报错位置对应的**动作**是我以为的那个吗？
