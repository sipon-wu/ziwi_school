## B1 试卷库未按教师隔离（阻断 · 已修复并部署 staging）

- **现象**：`GET /api/exams` 对数学教师返回 **677 份**试卷（全校所有教师），应只返回本人。导致题库/试卷库列表计数错乱（语文/数学/英语显示 8 行=27 份分页首页、物理/化学/生物/历史/地理显示 6 行=跨教师同名学科试卷串入）。
- **根因**：`code/backend/internal/repository/exam_repo.go` 的 `ExamRepository.List(schoolID)` 仅按 `school_id` 过滤，缺 `teacher_id`；`exam_handler.go:ListExams` 也未传入当前用户。对比题库 `QuestionHandler.ListByTeacher` 是按教师隔离的，二者不一致。
- **修复**：
  - `exam_repo.go`：`List(schoolID, teacherID string)` → `WHERE school_id=? AND teacher_id=?`。
  - `exam_handler.go`：`ListExams` 取 `c.Get("user_id")` 传入。
- **验证**：数学教师 `/api/exams` 现返回 27 份（本人，每年级 3 份）；重跑 e2e 试卷库全部 `行数=3`，0 FAIL。
- **状态**：✅ 已修复 + 部署 staging 验证通过。

## B2 题库题型列映射缺失（非阻断 · ✅ 已修复）

  - `Exercises.tsx`：移除不完整的本地 `TYPE_LABELS`，题型列与筛选下拉统一使用全局 `QUESTION_TYPE_LABELS`。
- **状态**：✅ 已修复，待部署 staging 后重跑 e2e 验证。

## B3 题库缺 status 字段（非阻断 · ✅ 已验证为误判，非 bug，撤销）

- **结论**：经实测 `/api/exercises`（如语文教师）返回 `status` 字段**正常派生**：`audit_status=approved` → `status=published`，20 题全部 `published`，统计条「已发布 20 / 草稿 0」正确，**不存在 0/0 或恒显草稿**。
- **原误判来源**：仅 grep 数据库发现 `questions` 表无 `status` 列（列名为 `audit_status`），便猜测前端拿不到状态；未实测 API 就记为 bug，违反「先求证后结论」。
- **机制说明**：`Question.Status` 标记为 `gorm:"-"`（不落库），由 `repository.Question.AfterFind` 钩子从 `audit_status` 派生 `published/draft`；`CreateQuestion` 默认写 `audit_status=approved`，故新建/种子题均为已发布。
- **状态**：❌ 已撤销（非代码缺陷）。

## B4 无班级教师无法在 UI 切换年级（非阻断 · ✅ 已修复）

- **现象**：本次 14 个学科种子教师均无 `teacher_classes` 记录，头部学科/年级选择器在无班级时只显示静态文本「{学科} · 四年级」，无下拉，**无法在 UI 切换到其他年级**查看数据。
- **数据核实**：每学科 9 个年级 × 3 题/3 卷均已落库（API 验证数学教师本人 27 份、四年级 3 份），数据齐全，仅 UI 导航受限。
- **修复**：`code/frontend/src/components/AppLayout.tsx` 头部「无班级」分支由静态文本改为「学科 · 年级下拉」，`<select>` 绑定 `teaching.grade`，可切换全部 9 个年级（无班级教师仅能切年级，学科固定为本学科，符合其身份）。有班级教师仍走原班级选择器。
- **状态**：✅ 已修复 + 部署 staging + e2e 验证（一年级/四年级/九年级各 3 行，0 WARN）。

## B5 题库 >20 题被静默截断（阻断 · ✅ 已修复）

- **现象**：B4 验证时发现语文种子教师（28 题）切到一年级/九年级列表仅显示 1 行，但库内该年级实际 3 题——部分题目在 UI 不可见。
- **根因**：`exercise_handler.go` 的 `ListQuestions` 将 `pageSize` 写死为 `20`，前端 `Exercises.tsx` 仅取第一页 20 条后做客户端过滤/分页，导致题目数 >20 的教师被截断丢题（数据越权式丢失，非权限问题）。
- **修复**：
  - `exercise_handler.go`：`ListQuestions` 读取 `?page_size=` 查询参数（上限 2000），前端传 `?page_size=1000` 一次性取全量（前端自身再做 8 条/页分页）。
  - `Exercises.tsx`：列表请求改为 `/exercises?page_size=1000`。
- **状态**：✅ 已修复 + 部署 staging + e2e 验证（各年级完整 3 行）。
