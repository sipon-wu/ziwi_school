### 1.3 关键架构决策

| # | 决策 | 依据 |
|---|------|------|
| 1 | **Go 单体 + Python AI + Nginx 三层** | MVP 阶段效率优先，内部包边界清晰，后期可拆分微服务 |
| 2 | **PostgreSQL + pgvector** | 一套数据库零额外运维，课标+运营+运维多知识库统一管理 |
| 3 | **Redis 做异步队列** | MVP 日均万级消息，Redis 足够，不上 Kafka |
| 4 | **不使用 Node.js** | 减少语言栈，通知/推送逻辑并入 Go |
| 5 | **Docker Compose 单机** | 2-3 校试点阶段单机足够，不上 K8s |
| 6 | **Shared DB + RLS + GORM Scope** | 三层数据隔离（DB层+应用层+缓存层），安全底线 |
| 7 | **SSE 流式推送** | 教案/组卷生成逐段推送，提升体感速度 |
| 8 | **结构化 JSON 编辑器** | 教师只管"写什么"，不管"长什么样"，视觉排版由 AI 转换层处理 |
| 9 | **品牌色 #02A7F0** | 与设计系统完全对齐 |

## 三、数据库设计

### 3.1 设计原则

1. **角色驱动**：表结构支撑 8 种角色的数据隔离和权限边界
2. **多租户隔离**：school_id 行级隔离 + RLS 强制 + GORM Scope 双保险
3. **JSONB 灵活性**：教案内容、题目八要素、批阅维度等半结构化数据用 JSONB
4. **向量检索**：pgvector 管理多知识库（课标 + 教材 + 运营 + 运维）
5. **审计追踪**：所有关键操作记录审计日志，保留 180 天

### 3.2 核心 ER 关系

```
school ──┬── class ──┬── teacher_class (教师-班级-学科)
         │            ├── student_class (学生-班级)
         │            └── assignment (作业)
         │
         ├── user (8种角色: teacher/head_teacher/research_lead/
         │         registrar/principal/it_admin/platform_ops/platform_devops
         │         + student + parent)
         │
         ├── textbook_version (教材版本)
         ├── knowledge_node (知识图谱节点)
         └── curriculum_standard (课标条目，含 embedding)
```

```sql
    phone VARCHAR(20) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(30) NOT NULL CHECK (role IN (
        'teacher', 'head_teacher', 'research_lead',
        'registrar', 'principal', 'it_admin',

    email VARCHAR(200),

    wechat_openid VARCHAR(100),                 -- 微信绑定
    status VARCHAR(20) DEFAULT 'active',        -- active/disabled/left
    phone_updated_at TIMESTAMPTZ,               -- 手机号修改时间（月限1次）
    left_at TIMESTAMPTZ,                        -- 离职/毕业时间
    successor_id UUID REFERENCES users(id),     -- 继任者（离职交接）

    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 班级
CREATE TABLE classes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    school_id UUID REFERENCES schools(id) NOT NULL,

);

-- 学生-班级关联
CREATE TABLE student_classes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id UUID REFERENCES users(id) NOT NULL,
    class_id UUID REFERENCES classes(id) NOT NULL,
    enrolled_at TIMESTAMPTZ DEFAULT NOW(),

);

-- 家长-学生关联
CREATE TABLE parent_students (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    parent_id UUID REFERENCES users(id) NOT NULL,
    student_id UUID REFERENCES users(id) NOT NULL,
    relationship VARCHAR(20) DEFAULT 'parent',   -- parent/guardian
    is_primary BOOLEAN DEFAULT TRUE,
    UNIQUE (parent_id, student_id)
);

-- 教材版本
CREATE TABLE textbook_versions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    school_id UUID REFERENCES schools(id),       -- NULL=平台级
    subject VARCHAR(20) NOT NULL,
    grade VARCHAR(20),
    publisher VARCHAR(100) NOT NULL,              -- 出版社
    version_name VARCHAR(200) NOT NULL,           -- 如"人教版·四年级下册"
    scope VARCHAR(20) DEFAULT 'school',           -- platform/school
    status VARCHAR(20) DEFAULT 'active',          -- active/pending_audit/removed
    submitted_by UUID REFERENCES users(id),
    source_pdf_url VARCHAR(500),                  -- 自编教材 PDF
    auto_extracted BOOLEAN DEFAULT FALSE,         -- AI 自动提取
    created_at TIMESTAMPTZ DEFAULT NOW()
```

```go
func LicenseGuardMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        schoolID := c.GetString("school_id")
        license := licenseService.GetActiveLicense(schoolID)
        if license == nil || license.Status == "expired" {
            // 仅允许 GET/HEAD 请求（只读），拦截 POST/PUT/PATCH/DELETE
            if c.Request.Method != "GET" && c.Request.Method != "HEAD" {
                c.JSON(403, gin.H{"code": "LICENSE_EXPIRED", "message": "License已过期，仅支持查看已有内容。请联系管理员续费。"})
                c.Abort()
                return
            }
        }
        c.Next()
    }
}
```

## 四、API 设计原则

### 4.1 RESTful 规范

- **URL 格式**：`/api/v1/{resource}`，复数名词
- **认证**：Header `Authorization: Bearer {jwt_token}`
- **分页**：`?page=1&page_size=20`，返回 `{items, total, page, page_size}`
- **错误格式**：`{code: string, message: string, detail?: string}`
- **排序**：`?sort=created_at&order=desc`
- **筛选**：`?status=draft&subject=语文`

### 4.2 JWT 鉴权

- **算法**：RS256 非对称签名
- **Payload**：`{user_id, school_id, role, exp, iat}`
- **有效期**：Access Token 2h，Refresh Token 7d
- **刷新**：`POST /api/v1/auth/refresh`，返回新 Token 对

### 4.3 RBAC 权限模型（8角色）


### 6.3a 学科穿透组

支持跨学科知识交叉，小微在创建教案/出题时可启用穿透组：

| 穿透组 | 包含学科 | 典型场景 |
|--------|----------|----------|
| 人文组 | 语文/历史/地理/道法 | 语文课融入历史背景 |
| 数理组 | 数学/物理 | 物理题中的数学运算 |
| 生化组 | 生物/化学 | 跨学科实验 |
| 艺术组 | 美术/音乐 | 艺术鉴赏融合 |
| 语言组 | 英语 | 独立，不与中文组交叉 |

实现方式：
- 知识图谱节点增加 `cross_subject_links UUID[]` 字段存储跨学科关联边
- 教师创建教案/出题时可选择穿透组，知识图谱展示跨学科关联节点
- AI prompt 注入穿透组上下文，输出时标识节点来源学科（如「来自历史·唐代文学」）
- 默认不穿透，教师主动选择后启用

### 6.3b 小微面板三板斧（SOP/FAQ/资源推荐）

小微侧边面板提供三种快捷入口，降低教师使用门槛：

| 入口 | 说明 | 示例 |
|------|------|------|
| **SOP（标准操作流程）** | 常用教学任务的分步引导 | "帮我生成一份教案" → 引导输入课题/单元/模板 |
| **FAQ（常见问题）** | 高频教学问题预设问答 | "如何让课堂导入更有趣？""如何设计分层作业？" |
| **资源推荐** | 基于当前上下文的智能推荐 | 推荐同单元的优秀教案/练习题/素材 |

前端实现：`XiaoWeiPanel.tsx` 在空会话状态下展示三板斧入口卡片，点击后自动填充 prompt 或触发 SOP 流程。

### 6.5 AI 生成流程（教案为例）

```
教师点击"生成教案"
  → business-api 接收请求，创建 task_id
  → business-api 异步调用 ai-service
  → ai-service:
      1. RAG 检索课标（bge-large-zh 向量化 → pgvector Top-5）
      2. Prompt 编排（System Prompt + 课标约束 + 格式要求 + 教师风格）
      3. 调用通义千问 API (stream=True)
      4. 每收到 token → SSE 推送前端
      5. 安全后处理（内容审核 + 幻觉检测 + 格式校验 + 善意度审查）
      6. 存储完整教案到 PostgreSQL
  → 前端 ProseMirror/contentEditable 实时渲染
  → 生成完成后展示 AI 生成依据（可解释性）
```

### 6.6 AI 可解释性

所有 AI 生成内容必须展示「生成依据」：

| 生成类型 | 展示依据 |
|----------|----------|
| 教案生成 | 所选知识点清单 / 模板类型 / 引用素材列表 / 参考风格特征 |
| 智能组卷 | 知识点覆盖率 / 难度分布 / 选题来源（学情薄弱点/教师偏好） |
| 学情评估 | 数据来源说明 / 对比基准 / 时间范围 |
| 个性化方案 | 双评估摘要（小微数据评估 + 教师观察描述） |

### 6.7 非工作会话识别（三层防护）

| 层 | 机制 | 说明 |
|----|------|------|
| 第一层 | System Prompt 锚定 | 明确声明工作边界 |
| 第二层 | 意图分类 | 轻量级分类模型（教学/运维/通用/违规） |
| 第三层 | 内容审核 | 相关性判断，低于阈值礼貌拒绝 |

逐级上浮提醒：第1次友善提醒 → 第2次稍重提醒 → 第3次警示上报（按周重置计数）

```nginx
        proxy_pass http://backend-api:8080;

        proxy_set_header X-Real-IP $remote_addr;

        proxy_buffering off;
        proxy_cache off;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
    }
}
```
